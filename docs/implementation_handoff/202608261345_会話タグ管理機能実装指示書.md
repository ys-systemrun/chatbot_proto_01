### 5.5 `agent_invitro`: `src/tags.py`（新設, T6）

`select_tags`呼び出し結果のパース、継続タグ判定、複数回`search_knowledge`呼び出しと重複排除をまとめる新規モジュール。`main/api/server.py`の`_extract_results`と対になる`_extract_selected_tags`をこのモジュール内に複製する（`select_tags`と`search_knowledge`は別ツールであり戻り値の形も異なるため、既存の`_extract_results`をそのまま流用しない）。

```python
"""会話タグのマージ・継続判定・複数回検索ロジック（IMPL-202608261345 T6, ADR-0057）。"""

from __future__ import annotations

import asyncio
import json
import logging
from dataclasses import dataclass

logger = logging.getLogger(__name__)


@dataclass
class TagState:
    id: int
    name: str
    score: float
    missed_turns: int


def _extract_selected_tags(raw) -> list[dict]:
    """select_tags の戻り値（{"selected": [...]}）から selected 配列を頑健に取り出す。

    server.py の _extract_results と同様、langchain_mcp_adapters のバージョン差
    （JSON文字列・タプル・dict等）を吸収する。
    """
    data = raw
    if isinstance(data, tuple):
        data = data[0]
    if isinstance(data, (bytes, bytearray)):
        data = data.decode("utf-8")
    if isinstance(data, str):
        try:
            data = json.loads(data)
        except json.JSONDecodeError:
            return []
    if isinstance(data, dict):
        selected = data.get("selected", [])
        return selected if isinstance(selected, list) else []
    return []


def compute_conversation_tags(
    new_tags: list[dict],
    client_tags: list,  # main/api/server.py の ConversationTag のリスト（id/name/score/missed_turns属性を持てばよい）
    max_missed_turns: int,
    max_tags: int,
) -> list[TagState]:
    """select_tags結果とクライアント由来タグをマージし、継続タグを判定する（要件定義書6.4.3節）。

    戻り値はそのリクエストの検索（search_with_merged_tags）にも、
    レスポンスの継続タグ（Response.tags）にも、同一の集合として使う。
    """
    new_by_id = {t["id"]: t for t in new_tags}
    updated: dict[int, TagState] = {}

    # 1-2. クライアント由来タグ: 再選択されていれば missed_turns=0・score更新、
    #      されていなければ missed_turns+1
    for ct in client_tags:
        if ct.id in new_by_id:
            nt = new_by_id[ct.id]
            updated[ct.id] = TagState(
                id=ct.id, name=nt["name"], score=nt["score"], missed_turns=0
            )
        else:
            updated[ct.id] = TagState(
                id=ct.id, name=ct.name, score=ct.score, missed_turns=ct.missed_turns + 1
            )

    # 3. 新規タグの追加（クライアント側に無かったもの）
    for t in new_tags:
        if t["id"] not in updated:
            updated[t["id"]] = TagState(
                id=t["id"], name=t["name"], score=t["score"], missed_turns=0
            )

    # 4. missed_turns がしきい値を超えたタグを破棄
    tags = [t for t in updated.values() if t.missed_turns <= max_missed_turns]

    # 5. 上限件数を超える場合は missed_turns 降順 → score 昇順で間引く
    if len(tags) > max_tags:
        tags.sort(key=lambda t: (-t.missed_turns, t.score))
        tags = tags[:max_tags]

    return tags


async def search_with_merged_tags(
    search_tool,
    extract_results_fn,  # server.py の _extract_results をそのまま渡す
    query: str,
    merged_tags: list[TagState],
    top_k: int,
    fallback_enabled: bool,
) -> list[dict]:
    """マージタグ1件につき1回＋フォールバック1回、search_knowledgeを並列呼び出しし、
    QA単位（結果dictのidキー）で重複排除・スコア降順に統合する（要件定義書6.4.2節）。

    tags引数のAND制約（1回のtags引数に複数タグをまとめると全タグを同時に持つQAしか
    ヒットしなくなる）を、タグ別に呼び出しを分けることで回避する（ADR-0057）。
    """
    calls = [
        search_tool.ainvoke({"query": query, "tags": [t.name], "top_k": top_k})
        for t in merged_tags
    ]
    if fallback_enabled:
        calls.append(search_tool.ainvoke({"query": query, "top_k": top_k}))

    if not calls:
        return []

    raw_results = await asyncio.gather(*calls, return_exceptions=True)

    by_id: dict[str, dict] = {}
    for raw in raw_results:
        if isinstance(raw, Exception):
            logger.warning("search_knowledge call failed during tag-merged search: %s", raw)
            continue
        for doc in extract_results_fn(raw):
            doc_id = doc.get("id")
            if doc_id is None:
                continue
            if doc_id not in by_id or doc.get("score", 0) > by_id[doc_id].get("score", 0):
                by_id[doc_id] = doc

    merged = sorted(by_id.values(), key=lambda d: d.get("score", 0), reverse=True)
    return merged[:top_k]
```

## 10. 実装時の注意点・落とし穴

- **`web_backend`（中継層）のスキーマ追加を忘れない**: 「AWS環境のみを対象とする」というスコープ（要件定義書4.1節）から、`chat_controller.py`（`web_backend`）への変更が不要だと誤解しやすいが、AWS中継処理が`req.model_dump()`で一度自前のモデルにパースし直しているため、5.3節の変更を省略すると`tags`がAWS環境でも中継時に失われる（要件定義書6.3節）。
- **`search_knowledge`の`tags`引数はAND条件**: マージタグ全件を1回の`tags`引数にまとめて渡さないこと。5.5節の`search_with_merged_tags`のように、タグ1件ごとに個別の呼び出しへ分ける（ADR-0057コンテキスト）。
- **重複排除キーは結果dictの`id`**: `metadata.guid`ではなく、トップレベルの`id`キー（`Document.id`と同一値）を使う。5.5節の実装を参照。
- **複数回の`search_knowledge`呼び出しは並列化する**: 逐次`await`ではなく`asyncio.gather`を使うこと。マージタグ数（最大`TAG_CONTEXT_MAX_TAGS`）＋フォールバック1回分の呼び出しを逐次実行すると、レイテンシが呼び出し回数に比例して増加する（0章）。
- **`select_tags`失敗時にリクエスト全体を失敗させない**: `tags_tool.ainvoke(...)`は`try/except`で囲み、失敗時は`new_tags = []`として処理を継続する（既存の`search_knowledge`呼び出し失敗時にリクエスト全体を失敗させる既存挙動とは異なる扱いである点に注意。既存挙動を変えるものではなく、`select_tags`という新規呼び出しに限った方針である）。
- **`agent_invitro`と`web_backend`で`ConversationTag`の定義を一致させる**: 既存方針（コンポーネント間でコードを共有せず複製する）に従い、Pydanticモデル自体は`chat_controller.py`と`server.py`それぞれに複製するが、フィールド名・型（`id: int`, `name: str`, `score: float`, `missed_turns: int`）を完全に一致させること。一方だけフィールドを追加し忘れる、型を変える等の食い違いがあると、中継時にシリアライズ・デシリアライズが失敗する。
- **`graph/agent.py`・`main/ipython/main.py`には触れない**: 本機能は`main/api/server.py`（AWS限定のHTTPサーバー）のみを対象とする。ADR-0022のReActエージェント自体の変更は本書のスコープ外である。
- **ローカル`docker-compose.yml`への環境変数追加は不要**: 5.4節の新規環境変数は、AWS限定で起動する`main/api/server.py`でのみ参照される。ローカルの`agent_invitro`サービスは引き続き`sleep infinity`であり、これらの環境変数を読む主体が存在しない。

## 0. 本書作成にあたり確定した事項

要件定義書2.3節相当の確認事項に加え、本書作成にあたり新たに確定・明確化した事項を示す。

| 項目 | 決定内容 | 根拠・備考 |
|---|---|---|
| 更新時の`parent_name`空欄の意味 | **本書での確定事項。** 要件定義書6.1節（空欄はルート直下）と6.2節（空欄は既存値を維持する部分更新）は、新規作成時と更新時とで意味が異なることを明確化していなかった。実装は次の通り区別する: **新規作成**（`name`が既存タグに一致しない）時、`parent_name`空欄は「親なし＝ルート直下」を意味する。**更新**（`name`が既存タグに一致）時、`parent_name`空欄は「変更なし＝既存の親を維持する」を意味する（`move_tag`を呼び出さない）。ルート直下へ明示的に移動させたい場合は、別途`TagTreePage`の個別編集（移動UI）を使う（本書のCSVフォーマットではルート直下への明示的な移動は表現できない。5.4節Open Issueとして記載）。 |
| 更新時の`description`空欄の意味 | 要件定義書6.1節・6.2節の記載通り、空欄は「変更なし＝既存値を維持する」。空文字列で明示的に説明文を消去する操作は本機能では扱わない（既存の`TagTreePage`個別編集で行う）。QA一括インポート（ADR-0053）の`title`/`question_text`等と同じ制約 |
| `name`重複行（同一CSV内）の扱い | CSV内に同じ`name`の行が複数ある場合、**後勝ち**（後の行の内容で上書き）とする。1行目の処理結果で新規作成、2行目でその作成済みタグに対する更新として扱われる（内部的には`resolved_names`に登録済みのため、2行目以降は「既存タグの更新」経路を通る） |
| CSVパース・文字コード | 既存のQA一括インポート（`_parse_qa_import_csv`）と同一方式（UTF-8, BOM付き可、`csv.DictReader`）を踏襲する |
| `import_tag_batch`の配置 | `TagRepository`のメソッドとして追加する（`QaManagementRepository.import_qa_batch`と同じ配置方針。既存の`create_tag`/`move_tag`/`set_tag_description`を内部で再利用する） |

### 5.1 `TagRepository.import_tag_batch`の実装（T1、ADR-0061）

`tag_repository.py`に追加する。既存の`create_tag`/`move_tag`/`set_tag_description`（循環参照チェック・重複チェックを含む）を内部で呼び出す薄いラッパーとして実装する。

```python
def import_tag_batch(self, rows: List[dict]) -> List[dict]:
    """CSVの各行（dict: name, parent_name, description）をまとめて登録・更新する。

    - `name`が既存タグと一致すれば更新（0節: parent_name/descriptionが空欄なら変更なし）、
      一致しなければ新規作成する（0節: parent_name空欄はルート直下）。
    - `parent_name`は、既存タグまたは同一CSV内の他行のnameで解決する。CSV内の行の並び順には
      依存しない（複数パスによる反復解決、ADR-0061）。
    - 循環参照は既存のcreate_tag/move_tagのバリデーションで検出する。
    - 戻り値: [{"row": <行番号>, "status": "success"|"error", "tag_id": ..., "error": ...}, ...]
    """
    results: List[Optional[dict]] = [None] * len(rows)

    with self.db.cursor() as cur:
        cur.execute("SELECT name, id FROM tag")
        resolved_names: Dict[str, int] = {name: tid for name, tid in cur.fetchall()}

    remaining = list(range(len(rows)))
    progress = True
    while remaining and progress:
        progress = False
        still_remaining = []
        for i in remaining:
            row = rows[i]
            name = (row.get("name") or "").strip()
            parent_name = (row.get("parent_name") or "").strip()
            description = (row.get("description") or "").strip() or None

            if not name:
                results[i] = {"row": i, "status": "error", "error": "name is required"}
                progress = True
                continue

            # parent_name が指定されていて、まだ解決できていない場合は次パスへ繰り越す
            if parent_name and parent_name not in resolved_names:
                still_remaining.append(i)
                continue

            parent_tag_id = resolved_names.get(parent_name) if parent_name else None

            try:
                if name in resolved_names:
                    # 既存（またはこのバッチ内で作成済み）タグの更新
                    tag_id = resolved_names[name]
                    if parent_name:  # 空欄=変更なし（0節）
                        self.move_tag(tag_id, parent_tag_id)
                    if description is not None:  # 空欄=変更なし
                        self.set_tag_description(tag_id, description)
                else:
                    node = self.create_tag(
                        name=name, parent_tag_id=parent_tag_id, description=description
                    )
                    tag_id = node.id
                    resolved_names[name] = tag_id
                results[i] = {"row": i, "status": "success", "tag_id": tag_id}
            except TagError as e:
                results[i] = {"row": i, "status": "error", "error": str(e)}
            progress = True

        remaining = still_remaining

    # 反復終了後も残っている行 = parent_name が既存タグにもCSV内の他行にも見つからない
    for i in remaining:
        parent_name = (rows[i].get("parent_name") or "").strip()
        results[i] = {
            "row": i,
            "status": "error",
            "error": f"parent tag '{parent_name}' not found (neither in existing tags nor in this CSV)",
        }

    return results
```

補足:

- `move_tag`/`create_tag`は循環参照検出時に`TagError`を送出する（既存実装、ADR-0006）。CSV内で循環する親子関係（例: 行AのparentがB、行BのparentがA）を指定した場合、多段解決の過程でどちらの行も「相手が未解決」のまま`progress`が立たなくなり、最終的に「`parent tag ... not found`」として両行がエラー報告される（循環参照特有の専用メッセージにはならない点に留意。5.5節参照）。
- 既存の`create_tag`/`move_tag`/`set_tag_description`はそれぞれ独立したDBカーソル（`with self.db.cursor()`）でコミットするため、`import_tag_batch`全体は単一トランザクションではなく、既存の`import_qa_batch`（ADR-0053）と同様、行単位で独立してコミットされる。

### 5.3 web_backend: CSVアップロードAPI（T3、ADR-0061）

`tag_controller.py`に、QA一括インポート（`qa_controller.py`の`_parse_qa_import_csv`/`import_qa_csv`、5.6節参考）と同一パターンでCSVパース・呼び出し処理を追加する。

```python
import csv
import io

# CSV 一括インポートで受け付ける列（IMPL-202608261630 T3 / ADR-0061）。
_TAG_IMPORT_COLUMNS = ["name", "parent_name", "description"]


class TagImportRowResult(BaseModel):
    row: int
    status: str
    tag_id: int | None = None
    error: str | None = None


class TagImportResponse(BaseModel):
    total: int
    success_count: int
    results: list[TagImportRowResult]


def _parse_tag_import_csv(csv_bytes: bytes) -> list[dict]:
    """CSV（UTF-8, BOM付き可）をパースして import_tag_batch へ渡す行データに整形する。
    列の機械的なバリデーション（必須列の存在チェック）のみをここで行い、業務バリデーション
    （name必須・循環参照チェック等）は Knowledge MCP に委ねる（ADR-0061）。
    """
    try:
        text = csv_bytes.decode("utf-8-sig")
    except UnicodeDecodeError:
        raise HTTPException(
            status_code=422, detail="CSV は UTF-8（BOM 付き可）で保存してください。"
        )
    reader = csv.DictReader(io.StringIO(text))
    if reader.fieldnames is None:
        raise HTTPException(status_code=422, detail="CSV のヘッダー行がありません。")
    fields = {f.strip() for f in reader.fieldnames if f}
    if "name" not in fields:
        raise HTTPException(status_code=422, detail="CSV に必要な列がありません: name")
    return [
        {col: (raw.get(col) or "").strip() for col in _TAG_IMPORT_COLUMNS}
        for raw in reader
    ]


async def import_tags_csv(csv_bytes: bytes) -> TagImportResponse:
    """CSV をパースし、Knowledge MCP の import_tag_batch ツールを呼び出す。"""
    rows = _parse_tag_import_csv(csv_bytes)
    result = await _client.call_tool("import_tag_batch", {"rows": rows})
    log_admin_operation("import", "tag", None, {"total": result.get("total", len(rows))})
    return TagImportResponse(**result)
```

const [importResult, setImportResult] = useState<TagImportResponse | null>(null);

const fileRef = useRef<HTMLInputElement>(null);

    setImportResult(result);

  }
}

## 7. Open Issues（実装時に確定が必要な事項）

要件定義書12章のOpen Issueに加え、本書で新たに確認が必要な事項を示す。

1. **CSVフォーマットの最終確定**（要件定義書12章#1）: 区切り文字・文字コードの詳細を最終確定する。
2. **ファイルサイズ・件数上限**（要件定義書12章#2）: 実装フェーズで確定する。
3. **ルート直下への明示的な移動の表現方法**（本書0節で新たに判明した制約）: 現行のCSVフォーマットでは、既存タグを「ルート直下へ移動する」ことを明示的に表現できない（`parent_name`空欄＝変更なしのため）。この操作が必要な運用があるかどうかを発注者に確認し、必要であれば専用の表記（例: `parent_name`に`"(root)"`等の予約語を使う）を追加するかを検討する。
4. **エクスポート機能の要否**（要件定義書12章#3）: 本書のスコープ外。

## 9. 実装時の注意点・落とし穴

- **循環参照エラーのメッセージ**: 5.1節の多段解決アルゴリズムでは、CSV内の循環（AとBが互いを親として指定）は「相互に未解決のまま反復が進まなくなる」ことで検出され、最終的に両行とも「parent tag not found」のエラーメッセージになる。「循環参照です」という専用メッセージにはならない点に注意し、UI側のエラー表示文言でユーザーが原因を推測しやすいよう配慮する（またはメッセージ文言の改善を実装時に検討する）。
- **`move_tag`個別呼び出しのコスト**: 既存タグの更新で`parent_name`が指定されている場合、値が現在の親と同じであっても`move_tag`を呼び出す（差分チェックを行わない）。`move_tag`は循環参照チェックの再帰CTEを実行するため、大量行の更新時に無駄なクエリが発生しうる。パフォーマンス上問題になる場合は、実装時に「現在の`parent_tag_id`と一致する場合はスキップする」最適化を追加すること（5.1節の`resolved_names`に現在の`parent_tag_id`も保持すれば実装可能）。
- **既存の`create_tag`/`move_tag`のコミット粒度**: 5.1節補足の通り、行ごとに独立したカーソル・コミットになる。大量行のインポート中に処理が中断した場合、どこまで反映されたかを行番号から追跡できるよう、ログ出力（`log_admin_operation`は最終結果のみを記録するため、行単位の詳細は`TagImportResponse.results`のレスポンス自体に依存する）に留意すること。
- **CSVの文字コード・改行コード**: QA一括インポート（ADR-0053実装時の注意点）と同様、Windows環境で作成されたCSVはShift_JIS・CRLFの可能性がある。UTF-8（BOM付き含む）を前提としつつ、明示的なエラーメッセージを用意すること（5.3節で実装済みの想定）。

## 0. 本書作成にあたり確定した事項

| 項目 | 決定内容 | 根拠・備考 |
|---|---|---|
| `existing_tags`のDB型 | `verification_question.existing_tags TEXT`（タグ名のJSON配列文字列。`verification_run_tag.path`と同じ方式）。未設定は`NULL`、アプリケーション側では空配列として扱う | ADR-0060、要件定義書7.1節 |
| `新規タグ`の判定ロジックの実装場所 | `verification_controller.run_question()`内、`select_tags`のレスポンスを受け取った直後（Pythonのリスト内包表記による集合差分）。`verification_db`・`tag_selector_mcp`側には実装しない | **本書での確定事項**。要件定義書6.3節手順4 |
| `verification_run_tag.rank_no`の採番 | `select_tags`が返した順位ではなく、新規タグに絞り込んだ後のリスト内での連番（1始まり）とする。既存タグを除外した後の並びをそのまま使う（`select_tags`はscore降順で返すため、新規タグ同士の相対順位は保たれる） | **本書での確定事項** |
| `search_knowledge`への`tags`引数の組み立て | `既存タグ + 新規タグのtag_name`を`dict.fromkeys`で重複除去した1つの`list[str]`にまとめ、1回だけ呼び出す（ADR-0060、ADR-0058・0059の実装完了が前提） | ADR-0060 |
| 既存タグ選択UIのタグ一覧取得方法 | 既存の`GET /api/tags`（`api.ts`の`listTags()`、`TagTreePage`が既に使用）を再利用する。新規APIエンドポイントは追加しない | 要件定義書6.1節 |
| `existing_tags`の更新セマンティクス | `VerificationQuestionUpdateRequest.existing_tags`が`None`の場合は変更しない、値（空配列を含む）が指定された場合はその値で置き換える。既存の`question_text`/`memo`と同じ「送られた項目のみ更新」方針を踏襲する | **本書での確認事項** |

```python
async def run_question(question_id: int) -> VerificationRunOut:
    with VerificationDB(config.CONVERSATION_DB_URL) as db:
        question = db.get_question(question_id)
    if question is None:
        raise HTTPException(status_code=404, detail="verification question not found")

    max_tags = config.VERIFICATION_MAX_TAGS
    confidence_threshold = config.VERIFICATION_CONFIDENCE_THRESHOLD
    top_k = config.VERIFICATION_TOP_K
    min_score = config.VERIFICATION_MIN_SCORE
    snapshot = question.question_text
    existing_tags = list(question.existing_tags or [])  # IMPL-202608261510 T4

    # --- select_tags（引数は変更なし） -------------------------------------- #
    t0 = time.monotonic()
    try:
        tags_result = await _tag_selector_client.call_tool(
            "select_tags",
            {
                "query": question.question_text,
                "max_tags": max_tags,
                "confidence_threshold": confidence_threshold,
            },
        )
        tag_selector_latency_ms = int((time.monotonic() - t0) * 1000)
    except Exception as e:  # noqa: BLE001
        with VerificationDB(config.CONVERSATION_DB_URL) as db:
            run = db.create_run(
                question_id, snapshot, status="error",
                error_message=f"select_tags failed: {e}",
                max_tags=max_tags, confidence_threshold=confidence_threshold,
                top_k=None, min_score=None,
                tag_selector_latency_ms=int((time.monotonic() - t0) * 1000),
                knowledge_mcp_latency_ms=None,
                existing_tags_snapshot=existing_tags,  # 追加
                tags=[], sources=[],
            )
        return _to_run_out(run)

    # --- 新規タグの特定（既存タグに含まれないもの, IMPL-202608261510 T4 / ADR-0060） ------- #
    existing_set = set(existing_tags)
    new_selected = [
        t for t in tags_result.get("selected", []) if t["name"] not in existing_set
    ]
    tags = [
        VerificationTagRecord(
            rank_no=i + 1,  # 新規タグに絞った後の連番（0章）
            tag_id=t.get("id"),
            tag_name=t["name"],
            score=t.get("score"),
            path=t.get("path", []),
        )
        for i, t in enumerate(new_selected)
    ]

    # --- search_knowledge: 既存タグ＋新規タグを1回で渡す（ADR-0060、4章の前提に注意） ------ #
    merged_tag_names = list(dict.fromkeys(existing_tags + [t.tag_name for t in tags]))
    t1 = time.monotonic()
    try:
        search_result = await _knowledge_client.call_tool(
            "search_knowledge",
            {
                "query": question.question_text,
                "tags": merged_tag_names,
                "top_k": top_k,
                "min_score": min_score,
            },
        )
        knowledge_mcp_latency_ms = int((time.monotonic() - t1) * 1000)
    except Exception as e:  # noqa: BLE001
        with VerificationDB(config.CONVERSATION_DB_URL) as db:
            run = db.create_run(
                question_id, snapshot, status="error",
                error_message=f"search_knowledge failed: {e}",
                max_tags=max_tags, confidence_threshold=confidence_threshold,
                top_k=top_k, min_score=min_score,
                tag_selector_latency_ms=tag_selector_latency_ms,
                knowledge_mcp_latency_ms=int((time.monotonic() - t1) * 1000),
                existing_tags_snapshot=existing_tags,  # 追加
                tags=tags, sources=[],
            )
        return _to_run_out(run)

    sources = [
        VerificationSourceRecord(
            rank_no=i + 1, source_id=r.get("id"), source_type=r.get("source_type"),
            title=r.get("title"), content=r.get("content"), score=r.get("score"),
            metadata=r.get("metadata", {}),
        )
        for i, r in enumerate(search_result.get("results", []))
    ]

    with VerificationDB(config.CONVERSATION_DB_URL) as db:
        run = db.create_run(
            question_id, snapshot, status="success", error_message=None,
            max_tags=max_tags, confidence_threshold=confidence_threshold,
            top_k=top_k, min_score=min_score,
            tag_selector_latency_ms=tag_selector_latency_ms,
            knowledge_mcp_latency_ms=knowledge_mcp_latency_ms,
            existing_tags_snapshot=existing_tags,  # 追加
            tags=tags, sources=sources,
        )
    return _to_run_out(run)
```

## 9. 実装時の注意点・落とし穴

- **列インデックスのずれ**: `verification_db/db.py`の`list_questions`は、`q.existing_tags`を追加したことで`row[5]`以降のインデックスがすべて1つ後ろへずれる（5.2節参照）。既存コードをそのまま流用せず、インデックス番号を必ず見直すこと。
- **`existing_tags_snapshot`は`create_run`の呼び出し元（`run_question`の3箇所すべて）で渡すこと**: エラー時の2箇所（`select_tags`失敗時・`search_knowledge`失敗時）を含め、全ての`db.create_run(...)`呼び出しに`existing_tags_snapshot=existing_tags`を渡し漏れないこと（5.3節）。
- **`rank_no`は新規タグに絞り込んだ後の連番**: `select_tags`の元の順位（`tags_result.get("selected", [])`のインデックス）をそのまま使うと、既存タグが除外された分だけ歯抜けの番号になる。0章の方針通り、`new_selected`をフィルタしてから`enumerate`で振り直すこと。
- **IMPL-202608261450との実装順序**: 4章参照。本書のPhase 3は、`knowledge_mcp`側のタグマッチング方式変更が先に反映されていることを前提に単一呼び出しで実装している。

## 5. リソース仕様

### 5.1 モデル（T1）— `models/question_altered.py`

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import Optional


class QuestionAlteredError(Exception):
    """言い換え行の業務エラー（必須項目欠落・対象不存在・is_primary行への操作・qa_id不存在/付け替え）。"""


@dataclass
class QuestionAltered:
    id: int
    qa_id: str
    text: str
    is_primary: bool
    qa_title: Optional[str] = None

    def to_dict(self) -> dict:
        return {
            "id": self.id,
            "qa_id": self.qa_id,
            "qa_title": self.qa_title,
            "text": self.text,
            "is_primary": self.is_primary,
        }
```

### 5.2 リポジトリ（T2）— `repository/question_altered_repository.py`

`QaManagementRepository`と同じ流儀（`db.cursor()`ごとにコミット、embeddingはトランザクション外で先に計算、キャッシュしない）で実装する。`is_primary=false`を書き込みの不変条件として全メソッドで守る。

要点:
- `list_question_altered(qa_id, keyword, limit, offset)`: `is_primary=false`のみ。`qa_original.title`をLEFT JOINして`qa_title`を返す。件数（total）も返す。
- `get_question_altered(id)`: `is_primary`を問わず1件取得（存在しなければ`QuestionAlteredError`）。
- `create_question_altered(qa_id, text)`: `qa_id`存在検証→`embed_fn`→`is_primary=false`でINSERT。
- `update_question_altered(id, text)`: 対象の存在・`is_primary=false`を検証→`text`/embedding再計算。
- `delete_question_altered(id)`: 対象の存在・`is_primary=false`を検証→DELETE。
- `import_question_altered_batch(rows)`: `id`空欄=create、`id`一致=update。`is_primary`列は無視。`qa_id`付け替えは拒否。行単位エラー許容。戻り値 `[{"row","status","id"?,"error"?}]`。
- `export_question_altered()`: `is_primary=false`全件を`{id,qa_id,text,is_primary}`のdictリストで返す（ページングなし、`text`昇順・`id`昇順）。

実装は本書に添付の最終コード（実ファイル）を正とする。SQLは`qa_original.uuid = question_altered.qa_id`で結合し、外部キー制約が無い前提でLEFT JOINする。

### 5.3 MCPツール登録・DI（T3）

`server.py`: `QuestionAlteredRepository(db, embed_fn)`を生成し、`register_tools(...)`へ`question_altered_repository=...`で渡す。`tools.py`: `register_tools`のシグネチャに引数を追加し、既存QAツール群の後に7ツールを登録する。業務エラーは`except QuestionAlteredError as e: raise ToolError(str(e))`で変換する。

ツール名と引数（要件6.7）:
- `list_question_altered(qa_id?, keyword?, limit=20, offset=0)` → `{"items":[...], "total":n}`
- `get_question_altered(id)` → 詳細dict
- `create_question_altered(qa_id, text)` → 詳細dict
- `update_question_altered(id, text)` → 詳細dict
- `delete_question_altered(id)` → `{"deleted": id}`
- `import_question_altered_batch(rows)` → `{"total","success_count","results"}`
- `export_question_altered()` → `{"items":[{id,qa_id,text,is_primary}]}`

### 5.4 web_backend（T4）

`question_altered_controller.py`を新規追加。`qa_controller.py`・`tag_controller.py`と同一パターン（Pydanticモデル＋薄いMCP呼び出し＋`log_admin_operation`）。CSVパースは`_parse_import_csv`（必須ヘッダー`text`）。エクスポートはMCPの`export_question_altered`結果からCSV（UTF-8 BOM）を組み立て、`build_export_csv() -> (bytes, filename)`で返す。

## 9. 実装時の注意点・落とし穴

- **route順序**: `GET /api/question_altered/export`は`GET /api/question_altered/{item_id}`より前に登録する（後にすると`export`が`item_id`として解釈され、`int`パスパラメータ変換で422になる）。
- **embeddingはトランザクション外**: `create`/`update`はネットワーク呼び出し（LM Studio/Bedrock）を`db.cursor()`の外で先に済ませる（既存`create_qa`と同一）。
- **`import`のコミット粒度**: `create`/`update`が行ごとに独立コミットするため、`import_qa_batch`同様に単一トランザクションではない。部分成功時は`results`で行番号を追える。
- **CSV文字コード**: Windows作成CSVはShift_JIS/CRLFの可能性。UTF-8（BOM付き可）前提で明示的エラーメッセージを返す。
- **`qa_id`未存在の親**: `create`時に`qa_original`に存在しない`qa_id`はエラー。`import`でも行単位エラーとして報告する。

# ADR-0071: タグ新規作成時の類似候補チェック（非ブロッキング・簡易アルゴリズム方式）

- ステータス: Accepted
- 日付: 2026-09-02
- 関連: `docs/requirement/202609021050_タグ運用ガイドライン.md`、`docs/requirement/202609021102_タグ管理画面・タグ選択UI改修要件定義書.md`、ADR-0005、ADR-0008

## コンテキスト

タグ運用ガイドライン（202609021050）は、「ネットワーク認証」「ネット認証」のように、表記ゆれ（同一概念に複数の名前）や概念の混同（別概念を同じ／似た名前で運用してしまう）が実際に発生していることを課題として挙げ、新規タグ作成前に既存タグ・エイリアスを確認する運用手順（5章）を定めた。

現状、完全一致の重複は`hiroba_tag.name`の`UNIQUE`制約および`TagRepository.create_tag`のチェック（`TagError`）により作成時に拒否されるが、これは名前が完全に一致する場合のみを検出するものであり、「ネットワーク認証」と「ネット認証」のような近似的な表記ゆれは検出できない。この確認作業は現状、担当者の記憶と手作業でのタグ一覧確認に依存している。

## 決定

**`TagTreePage`の新規作成フォームに、入力中の名前と既存タグ名・エイリアスとの類似候補を計算し、非ブロッキングの警告として提示する機能を追加する。類似候補の提示は作成操作を妨げない。**

- 一致条件（MVP）: 次のいずれかを満たす既存タグ・エイリアスを類似候補とする。
  - 入力文字列が既存の名前／エイリアスを含む、または含まれる（部分文字列一致。全角・半角、大文字・小文字を正規化した上で比較する）。
  - 編集距離（Levenshtein距離）が閾値以下（初期値2文字を仮置きとし、実データでの試行を経て調整する）。
- 候補が見つかった場合、候補の名前・説明文・所属階層（親タグ名）を表示し、担当者が「別概念として続行する」か「既存タグ・エイリアスを使う（作成を中断する）」かを判断できるようにする。**作成自体はブロックしない**。
- 完全一致の重複は、従来通り`create_tag`の`TagError`（`hiroba_tag.name`の`UNIQUE`制約起因）で拒否する。本ADRはこれに加えて近似一致を検知する層を追加するものであり、既存の重複防止機構を置き換えるものではない。

## 検討した代替案

- **類似候補が見つかった場合に作成をブロックし、確認モーダルでの明示的な続行操作を必須にする（ハードバリデーション）**: 表記ゆれの見逃しを確実に防げる利点があるが、誤検知（本来別概念であるにもかかわらず類似候補として提示され、作成を阻まれる）のリスクが高い。タグ運用ガイドラインは「別概念であれば説明文で区別して両方残す」ことを正当な選択肢として認めており、これをブロッキングにすると運用上の判断より機械的な検出を優先することになり、ガイドラインの前提と矛盾するため不採用とした。
- **形態素解析・埋め込みベクトルによる意味的類似度判定**: 「ネットワーク認証」と「ネット認証」のような表記ゆれだけでなく、表記が大きく異なる同義語（例:「積算」と「歩掛」）も検出できる可能性があり精度は高いが、新たな依存ライブラリ・計算基盤（`tag_selector_mcp`が使うような埋め込み・LLM基盤）の導入が必要になり、MVPの実装コストとしては過剰と判断した。将来、誤検知・見逃しの実績を踏まえて拡張を検討する候補として残す。
- **完全一致のみの検知を維持する（現状維持）**: 実際に発生した表記ゆれの実例（「ネットワーク認証」「ネット認証」）を検出できないため不採用とした。

## 結果・影響

- `create_tag`のMCPツール・API・エラー仕様（`TagError`による完全一致重複の拒否）には変更を加えない。本ADRの機能は`TagTreePage`側の追加ロジックのみで完結する。
- 本チェックは新規作成時のみを対象とし、`rename_tag`（`TagTreePage`の「名称」変更、現状`window.prompt`によるUI）への適用要否は別途判断する（要件定義書202609021102 Open Issue #4）。
- 類似候補チェックの閾値・正規化ルール（長音記号統一等の表記ゆれ対応をどこまで含めるか）は、実データでの試行を経て調整が必要（要件定義書202609021102 Open Issue #5）。

# ADR-0062: `agent_invitro`の情報源検索を単一`search_knowledge`呼び出しに単純化する（ADR-0057の限定的な見直し）

- ステータス: Accepted（ADR-0057を限定的に改訂）。ただし本ADRが記した「報告事象の根本原因＝呼び出し方式の世代差」という診断はADR-0063により訂正された（真因はMCPアダプタ戻り値のパース欠陥で会話タグが常に空になっていたこと）。本ADRの単一呼び出し化の決定自体は維持する（差し戻さない）。
- 日付: 2026-08-27
- 関連: `docs/requirement/202608271040_agent_invitroタグマージ検索方式単純化要件定義書.md`, `docs/detected_problems/202608270951_チャット情報源検索結果検証ページとの差異調査報告.md`, ADR-0063（診断の訂正）, ADR-0057, ADR-0058, ADR-0059, ADR-0060, ADR-0056, ADR-0049, ADR-0043

## コンテキスト

ADR-0057（2026-08-26）は、`agent_invitro`の`POST /ask-sl`（`main/api/server.py`）における情報源検索方式として、「マージタグ1件につき1回`search_knowledge`を呼び出し＋タグ指定なしのフォールバック呼び出し1回＋結果をQA単位で最大スコア統合する」というワークアラウンド（`agent_invitro/src/tags.py`の`search_with_merged_tags`）を採用した。この決定は、当時`knowledge_mcp`の`search_knowledge`の`tags`引数が完全一致AND条件であり、マージタグ全件を1回の`tags`引数にまとめると、タグ数が増えるほど検索結果が0件に近づくリスクがあったことに基づく（ADR-0057コンテキスト2節）。

同日付のADR-0058（祖先タグの動的展開）・ADR-0059（タグ構成類似度と埋め込み類似度を統合したスコアリング方式）により、`search_knowledge`の`tags`引数は完全一致AND条件から「タグ類似度によるソフトなランキングシグナル」へ変更された。これにより、ADR-0057が対応していた0件化リスクは解消された（`docs/requirement/202608261450_タグ階層展開・タグ構成類似度スコアリング機能要件定義書.md`12章 Open Issue #1に、この変更後はADR-0057のワークアラウンドを単純化できる可能性が高いと明記されている一方、実装変更自体はスコープ外として見送られていた）。

検証機能（ADR-0060、`web_backend/src/main/controllers/verification_controller.py`）はADR-0058/0059以降に実装されたため、当初からマージタグ全件を1回の`search_knowledge`呼び出しで渡す方式になっている。一方`agent_invitro`側はADR-0057策定時のワークアラウンドのまま更新されず、両者の間に実装上の世代差が生じていた。

この世代差が原因で、AWS環境において、検証ページでは正しく情報源を取得できる質問に対し、実チャット（`agent_invitro`）では的外れな回答が返る不具合が確認された（`docs/detected_problems/202608270951_チャット情報源検索結果検証ページとの差異調査報告.md`）。ユーザーへの確認により、以下が判明している。

- 事象は会話の1ターン目から発生する（継続タグ判定ロジックの蓄積とは無関係に、タグ別複数回呼び出し＋フォールバック呼び出しの統合方式そのものが原因）。
- AWS環境では、この機能のリリース当初から一貫して発生していると見られる。
- ローカル環境での再現有無は未確認。

## 決定

**`agent_invitro/src/tags.py`の`search_with_merged_tags`（タグ別複数回呼び出し＋フォールバック呼び出し＋QA単位の最大スコア統合）を廃止し、検証機能（ADR-0060）と同一の「マージタグ全件を1回の`tags`引数にまとめて`search_knowledge`を呼び出す」単一呼び出し方式に置き換える。**

- マージタグが0件の場合も、同じ単一呼び出し（`tags=[]`）でよい。ADR-0059により「`tags`引数が指定されない場合と空配列の場合は同じ扱い」と定義されているため、従来のフォールバック呼び出し（`tags=None`）が担っていた「タグなし＝埋め込み類似度のみでの検索」という挙動は、単一呼び出しの`tags=[]`のケースで自然に得られる。したがって、別途フォールバック呼び出しを維持する理由はない。
- 環境変数`TAG_SEARCH_FALLBACK_ENABLED`は廃止する。
- ADR-0057が決定した他の要素（1節: `select_tags`の明示呼び出し、2節: クライアント由来タグとのマージ、4節: `missed_turns`によるしきい値方式の継続タグ判定ロジック）は変更しない。本ADRはADR-0057の3節（AND制約を回避するための検索方式）のみを置き換える、限定的な改訂である。
- `top_k`（現状ハードコードされた`3`）・`min_score`（現状未指定）の値は本ADRの時点では変更しない。検証ページの既定値（`top_k=5`）と揃えるかどうかは別途判断する（要件定義書12章 Open Issue #1）。

## 検討した代替案

- **現状維持（タグ別複数回呼び出し＋フォールバック＋最大スコア統合を維持する）**: 却下。本ADRの起票理由そのものであり、AWS環境で当初から実チャットの情報源検索が的外れになる不具合が確認されている。ADR-0057策定時に前提としていた「AND条件による0件化リスク」自体がADR-0058/0059により解消された今、このワークアラウンドを維持する技術的必要性がない。
- **フォールバック呼び出し（`tags=None`）だけは残し、タグ別複数回呼び出しのみを単一化する**: 却下。ADR-0059により`tags`引数のAND制約自体が撤廃されているため、フォールバック呼び出しを別途維持する理由がない。むしろ、単一呼び出し（マージタグ全件）の結果と、フォールバック呼び出し（タグなし・埋め込み類似度のみ）の結果を最大スコアで混在統合すると、スコアの尺度が異なる結果同士を比較することになり、今回の不具合と同種の問題（数学的に整合しないスコア混在）を再度招く。
- **`knowledge_mcp`の`search_knowledge`自体に変更を加える（例: 呼び出し1回で済むような新パラメータを追加する）**: 却下。`agent_invitro`側の呼び出し方法を検証機能と揃えるだけで目的（検証ページと同じ情報源検索結果を得る）を達成できるため、`tag_selector_mcp`・`knowledge_mcp`への変更は不要である（ADR-0058/0059の変更範囲を再度広げない）。
- **継続タグ判定ロジック（`missed_turns`等）自体も見直す**: 却下。ユーザー確認により、事象は継続タグの蓄積（2ターン目以降）とは無関係に1ターン目から発生することが分かっており、継続タグ判定ロジック自体に問題があるわけではない。今回の変更対象を検索呼び出し方式のみに限定する。

## 結果・影響

- `agent_invitro/src/tags.py`の`search_with_merged_tags`関数は、単一の`search_knowledge`呼び出しに単純化される（`asyncio.gather`による並列呼び出し・QA単位の重複排除・最大スコア統合ロジックは不要になり削除される）。
- `agent_invitro/src/main/api/server.py`の`_ask_impl`内の呼び出し部分・ログ出力を更新する。
- `agent_invitro/src/config.py`から`tag_search_fallback_enabled`関連の定義を削除する。
- `terraform/main/app/main.tf`の`module "agent_invitro"`の`environment`から`TAG_SEARCH_FALLBACK_ENABLED`を削除する。
- 1リクエストあたりの`search_knowledge`呼び出し回数が最大6回（既定値、ADR-0057）から1回に減り、レイテンシが改善する見込みである（ADR-0057の要件定義書12章 Open Issue #5が実質的に解消される）。
- ADR-0057は本ADRにより限定的に改訂される（3節の決定のみ本ADRの決定に置き換え、1・2・4節は維持）。ADR-0057のファイル冒頭のステータス行に本ADRへの参照を追記する。
- `docs/requirement/202608261450_タグ階層展開・タグ構成類似度スコアリング機能要件定義書.md`12章 Open Issue #1（ADR-0057ワークアラウンドの見直し要否）は、本ADRにより「見直しを実施する」と回答され、解消される。
- `top_k`・`min_score`の値統一、ローカル環境での再現確認、実チャットUIへの情報源表示については、本ADRのスコープ外の未決事項として要件定義書12章 Open Issueに記録済みであり、別途判断する。

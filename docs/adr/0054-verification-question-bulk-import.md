# ADR-0054: 検証質問データの一括インポート機能の実装方式（verification_db直接書き込み）

- ステータス: Accepted
- 日付: 2026-08-26
- 関連: `docs/requirement/202608261002_DBマイグレーション・データインポート機能要件定義書.md`, ADR-0048, ADR-0050

## コンテキスト

検索精度検証機能要件定義書（202608260909）4.2節は、「検証質問のCSV等によるインポート・エクスポート機能」を対象外としていた。検証質問（`verification_question`）は、`front_dev`の検証質問登録・編集フォームから1件ずつ登録するほかなく、想定される運用（数件〜数十件、場合によってはより多くの質問セットを検証対象として管理する、要件定義書202608260909 12章Open Issue #5）に対して、1件ずつの登録は負荷が大きい。

検証データ（`verification_question`/`verification_run`等）は、ADR-0048により「`chatbot`データベース・Knowledge MCP経由の書き込みとは異なり、`web_backend`が`conversation`データベースへ直接（`psycopg2`による生SQL）読み書きする」方式が確立している。これは、検証データが「QA・タグそのものではなく、実行・評価の記録という運用ログ的データである」という性質に基づく判断であり、一括インポート機能もこの既存方針を踏襲する。

## 決定

**`web_backend`の`verification_db`モジュールに、複数件の検証質問をまとめて登録する一括登録関数を追加する。Knowledge MCPは経由せず、既存の単発登録API（`POST /api/verification/questions`）と同じ`conversation`データベースへの直接書き込み方式を用いる。**

- **新規APIエンドポイント**: `web_backend`に`POST /api/verification/questions/import`（仮称）を新設し、CSVファイルをリクエストボディとして受け付ける。
- **CSVフォーマット**: `question_text`（必須）・`memo`（任意）の2列とする。`verification_question`テーブル自体に一意キーとなる項目がないため（要件定義書12章Open Issue #3）、本ADRでは重複判定を行わず、CSVの全行を新規`verification_question`として`INSERT`する。
- **`verification_db`の拡張**: 既存の単発登録関数（`create_question`相当、実装フェーズで命名確定）と同じSQL文をループまたはバルクINSERTで複数件に適用する`bulk_create_questions`（仮称）を追加する。
- **部分成功の扱い**: CSVの構文エラー（列不足等）は行単位で検出し、有効な行のみを登録する。空の質問文（`question_text`が空文字）の行はスキップし、エラーとして報告する。

## 検討した代替案

- **Knowledge MCP経由の方式に合わせる（`verification_question`もMCPツール化する）**: `chatbot`データベース側のQA一括インポート（ADR-0053）と実装方式を統一できる利点があるが、ADR-0048が既に「検証データは`chatbot`データベース・Knowledge MCPのドメインに含まれない」と明確に判断しており、この原則を一括インポート機能のためだけに崩す理由がない。既存方針との整合を優先し不採用とした。
- **全データインポート機能（ADR-0055）の枠組みで検証質問インポートも扱う（専用のCSVインポート機能を別途作らない）**: ADR-0055が扱う全データインポートは「エクスポート結果（SQLダンプ）の別環境への投入」という運用者向けの機能であり、日常的にQAデータ担当者がブラウザから検証質問を追加していく用途（本ADRが扱う一括インポート）とは利用者・利用頻度・データの性質が異なる。両者を同一の機能として扱うと、運用者向けの重い操作（DB全体への投入）と日常的な軽い操作（質問セットの追加）が混在し、UI・権限設計が複雑になるため、別機能として独立させることとした。

## 結果・影響

- `web_backend`の`verification_db`モジュール（202608260909の実装で新設予定）に、一括登録関数が追加される。既存の単発登録関数・APIには変更を加えない。
- `front_dev`の検証質問一覧ページに、CSVアップロードUIとインポート結果表示が追加される。
- 重複判定を行わないという本ADRの方針は、発注者確認（2026-08-26）により正式に決定した（要件定義書2.3節#8）。運用開始後に重複登録が問題になった場合は、別途ADRを起こして見直す。

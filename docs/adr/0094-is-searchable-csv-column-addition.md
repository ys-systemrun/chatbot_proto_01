# ADR-0094: CSV一括インポート／エクスポートへ is_searchable 列を追加する（省略時は「新規はtrue・既存は変更なし」）

- ステータス: Accepted
- 日付: 2026-09-16
- 関連: ADR-0047（全データエクスポートのダンプ生成・配信方式）、ADR-0053（QA・タグの一括インポート）、ADR-0064（言い換え質問文管理・CSVインポート/エクスポート）、ADR-0065（タグCSVエクスポート）、ADR-0066（全データインポートの全消去上書き方式）、ADR-0081（タグCSVへのエイリアス列追加）、ADR-0092（is_searchableの新設）、ADR-0093（管理UI・APIの方式）、`docs/requirement/202609160930_情報源レコード検索対象フラグ（is_searchable）機能要件定義書.md`（6.7〜6.8節）

## コンテキスト

ADR-0092で新設する `is_searchable` は、管理画面のトグル（ADR-0093）以外に、CSVによる一括操作でも扱えることが望ましい。大量のQAを一括投入したあとで一部だけを検索対象外にする、あるいは他環境の設定をそのまま移す、といった運用が想定されるためである。

本プロジェクトのCSV系機能は現在3系統ある。

| 機能 | 列 | 方向 |
|---|---|---|
| QA一括インポート（ADR-0053） | `uuid`, `title`, `question_text`, `answer_text`, `category_id`, `tags` | 入力のみ |
| 言い換え質問文（ADR-0064） | `id`, `qa_id`, `text`, `is_primary` | 入出力 |
| タグ（ADR-0061 / ADR-0065 / ADR-0081） | タグ名・親タグ名・説明・フォルダ・エイリアス等 | 入出力 |

これとは別に、全データエクスポート／全消去インポート（ADR-0047・ADR-0066）が、`web_backend/src/export/tables.py` の13テーブル定義に基づいてSQL/CSVを生成する。

列を増やす場合、**すでに運用者の手元にある既存CSVが通らなくなる**こと、および**列を省いたCSVで既存の設定が意図せず上書きされる**ことを避ける必要がある。ADR-0081（タグCSVへのエイリアス列追加）では「追加専用（既存エイリアスを削除しない）」という非破壊の解釈を採り、既存CSVとの互換を保った先例がある。

## 決定

**QA一括インポートと言い換え質問文のインポート／エクスポートに `is_searchable` 列を追加する。列そのものが無い場合・値が空欄の場合は「新規行は `true`、既存行は変更なし」と解釈する。タグCSVは対象外とする。**

### 決定1: 対象は2系統のCSVのみ

| CSV | 変更後の列 |
|---|---|
| QA一括インポート | `uuid`, `title`, `question_text`, `answer_text`, `category_id`, `tags`, **`is_searchable`** |
| 言い換え質問文 インポート | `id`, `qa_id`, `text`, `is_primary`, **`is_searchable`** |
| 言い換え質問文 エクスポート | `id`, `qa_id`, `text`, `is_primary`, **`is_searchable`** |

タグCSV（ADR-0065・ADR-0081）は対象外とする。タグは検索対象のレコードではなく分類メタデータであり、`is_searchable` 列を持たない（ADR-0092 決定1）。

トラブルシューティング記事にはCSV一括インポート機能が存在しない（ADR-0079で新規作成・削除を初期スコープ外とした）ため、本ADRの対象外である。記事の設定は管理UIおよび全データエクスポート／インポート（決定4）で扱う。

### 決定2: 値の解釈

- 受理する値は `true` / `false`（大文字小文字を区別しない）および `1` / `0` とする。
- これら以外の非空値は当該行のエラーとし、行単位でスキップする（既存のエラー許容方式を踏襲。1行の不正で全体が失敗しない）。
- エクスポートは実際の値を `true` / `false` の文字列で出力する。

日本語（`はい` / `いいえ` 等）は受理しない。既存CSVの `is_primary` 列がすでに `true` / `false` で往復している形式に揃える。

### 決定3: 省略時は「新規は `true`、既存は変更なし」

- **列自体が存在しない場合**（本機能追加前に出力・作成したCSV）と、**値が空欄の場合**を同一に扱う。
- 新規作成される行: `true`（DBの `DEFAULT` と同じ）。
- 既存行の更新: **変更なし**（現在の値を維持する）。

これにより、本機能追加前に取得した既存CSVをそのまま再インポートしても、管理画面で設定した検索対象外の状態が意図せず解除されない。ADR-0093 決定1で `update_qa` ・ `update_question_altered` の引数を「`None`＝変更なし」の部分更新としたことと、解釈が一致する。

「空欄＝`true`」ではない点が本決定の要である。空欄を `true` と解釈すると、列を持たない古いCSVで一括更新を行った瞬間に、除外していたレコードがすべて検索対象へ戻ってしまう。

### 決定4: 全データエクスポート／全消去インポートは列定義の追加のみで対応する

`web_backend/src/export/tables.py` の `hiroba_qa_original` ・ `hiroba_question_altered` ・ `troubleshooting_article` の `columns` 末尾および `_create_ddl` に `is_searchable BOOLEAN NOT NULL DEFAULT true` を追加する。

- SQLダンプの `INSERT` は列名を明示する形式であるため、**本変更前に取得した既存ダンプはそのまま投入でき、全レコードが `DEFAULT` の `true` となる**。
- 全消去インポート（ADR-0066）の事前自動バックアップは `information_schema` から列を動的に取得するため、追加の変更を要しない。
- エクスポート→全消去インポートの往復で、`is_searchable` の設定は保持される。

### 決定5: `export_question_altered` の出力項目も5項目へ拡張する

Knowledge MCPの `export_question_altered` は `id` / `qa_id` / `text` / `is_primary` を返し、CSVの組み立ては `web_backend` 側が行う（ADR-0064）。この責務分担は維持し、ツールの返す項目に `is_searchable` を加える。

## 検討した代替案

- **CSVには列を追加せず、管理UIのトグルのみとする**: 変更範囲が最小で、CSVの列構成を凍結できる。しかし数百件規模のQAを投入したあとで一部を検索対象外にする作業が、すべて画面上の1件ずつの操作になる。またエクスポート→再インポートの往復で設定が失われる（CSVに含まれないため）。運用の一括操作性を欠くため不採用とした（発注者の選択）。

- **空欄を `true` と解釈する（列が無い場合も一律 `true`）**: 解釈が1通りで実装も単純。しかし決定3に記したとおり、旧形式のCSVで一括更新した瞬間に除外設定が全解除される。CSVインポートは一括操作であるため、この事故は一度で広範囲に及ぶ。採用できない。

- **空欄を `false` と解釈する**: さらに危険であり検討に値しない（列を書き忘れた一括更新で情報源が全滅する）。

- **`is_searchable` 列を必須とし、欠けているCSVはエラーにする**: 解釈の曖昧さが無くなり、運用者に明示的な値を強制できる。しかし手元の既存CSV・外部で作成中のCSVがすべて即座に無効になり、移行の手間を運用者に押し付ける。ADR-0081で採った「既存CSVがそのまま通る」方針から外れる。

- **列名を `searchable` ・ `検索対象` 等にする**: CSVは運用者が直接編集するため、日本語見出しは分かりやすい。しかしDB列名・API項目名・MCPツール引数名がすべて `is_searchable` であり、CSVだけ別名にすると対応表が必要になる。既存CSVが `is_primary` ・ `category_id` といったDB列名そのままの見出しを使っている方針にも従う。

- **除外理由の列（`unsearchable_reason` 等）を併せて追加する**: 棚卸し時に有用。しかし本機能の要件に理由の記録は含まれておらず（要件定義書4.2節）、DB側にも列を持たないため、CSVだけに存在する列となってしまう。将来、理由の記録が要件化された時点でDBとCSVの双方に追加する。

- **トラブルシューティング記事のCSVインポート機能を本ADRで併せて新設する**: 3情報源のCSV対応が揃う。しかし記事の新規作成・削除を初期スコープ外とした判断（ADR-0079 決定3）を本ADRで覆すことになり、変更の範囲が `is_searchable` の追加を大きく超える。対象外とした。

## 結果・影響

- `web_backend/src/main/controllers/qa_controller.py` の `_QA_IMPORT_COLUMNS` に `is_searchable` を追加し、`question_altered_controller.py` の `_IMPORT_COLUMNS` ・ `_EXPORT_COLUMNS` を5列へ拡張する。値の解釈（`true`/`false`/`1`/`0`/空欄）は `knowledge_mcp` の `import_*_batch` 側に置き、`web_backend` は列の受け渡しに留める（既存の責務分担どおり）。
- `knowledge_mcp` の `import_qa_batch` ・ `import_question_altered_batch` ・ `export_question_altered` を更新する。不正値は当該行のみ `status: "error"` とし、他の行の処理は続行する。
- `web_backend/src/export/tables.py` の3テーブル定義に列を追加する。全データエクスポートの出力（SQL/CSV）は列が1つ増えるため、**出力ファイルを外部ツールで機械的に処理している運用がある場合は列追加への追随が必要**である。
- 本変更前に取得した既存のSQLダンプ・既存のCSVは、いずれもそのまま利用できる（決定3・決定4）。
- タグCSV（ADR-0065・ADR-0081）の列構成は変更しない。

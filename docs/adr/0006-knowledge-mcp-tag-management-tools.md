# ADR-0006: タグマスタ管理機能を Knowledge MCP のツールとして提供する（外部からの直接管理も許容）

- ステータス: Accepted
- 日付: 2026-08-04
- 関連: ADR-0005, `docs/requirement/202608041002.md`, 実装指示書 `docs/implementation_handoff/202608041013_implementation.md`

## コンテキスト

ADR-0005 にて、タグを `tag`（マスタ、`parent_tag_id` による自己参照）と `qa_tag`（QAとの関連）のリレーショナル構造で管理する方針を決定した。この `tag` テーブルに対する登録・リネーム・親子関係の編集（タグマスタ管理）を、どのコンポーネントが担うかが Open Issue として残っていた。

発注者より、「暫定的に Knowledge MCP 自身でもツールとして操作できるようにしつつ、別口（他の管理ツールや手動運用）でも管理する可能性がある」という方針が示された。

## 決定

Knowledge MCP サーバに、`search_knowledge` に加えて **タグマスタ管理用のMCPツール群** を追加する。あわせて、Knowledge MCP は `tag` テーブルの内容を **一切キャッシュせず、呼び出しの都度DBを参照する** 設計とし、他ツールや手動SQL等、Knowledge MCP以外の経路によるタグテーブルへの直接変更が、Knowledge MCP側の実装変更や再起動なしに即座に反映される状態を維持する。

追加するツール（詳細は実装指示書 5.6 節）:

- `list_tags`: タグ一覧（親子関係を含む木構造）の取得
- `create_tag`: 新規タグの作成（名称、任意で親タグ指定）
- `rename_tag`: タグ名称の変更
- `move_tag`: 親タグの変更（再配置）
- `delete_tag`: タグの削除（`qa_tag` からの参照や子タグが存在する場合はデフォルトで拒否する）

## 検討した代替案

- **タグ管理は Knowledge MCP のスコープ外とし、DBを直接操作する運用（別途管理ツール・手動SQL）のみとする**: シンプルだが、LangGraph Agent等、MCP経由のクライアントからタグ管理を行いたいという要望に応えられないため、暫定案としては採用しなかった。

## 結果・影響

- タグ管理の初期運用を Knowledge MCP 側だけで完結できる。
- `tag` テーブルをキャッシュしない設計のため、将来的に専用の管理画面や他ツールが同じテーブルを直接操作しても、Knowledge MCP側は変更なく追従できる。
- 一方で、MCPサーバに検索以外の書き込み系機能が加わるため、参照資料が提示していた「Knowledge MCPは検索実行に専念する」という当初方針からは責務がやや拡大する。将来、責務分離の観点でタグ管理専用の別MCPサーバへ切り出す可能性は残しておく（Open Issueとして追記）。
- 書き込み系ツール（`create_tag`/`rename_tag`/`move_tag`/`delete_tag`）は、`search_knowledge`のような読み取り専用ツールと異なり、誰が呼び出せるべきかというアクセス制御の検討が必要になる（要件定義書 Open Issue #4 と合わせて要検討）。
- `move_tag`/`create_tag` で親子関係を設定する際、循環参照（例: AをBの親にし、BをAの親にする）を防止するバリデーションが必要になる（実装指示書 5.6 節に検証手順を記載）。
- `delete_tag` の挙動（参照がある場合に拒否するか、cascade削除するか）は安全側に倒し、デフォルトは拒否とする。

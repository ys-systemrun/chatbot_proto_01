# タグエイリアス管理機能 要件定義書

- 起票日: 2026-09-09
- 起票者: Y（SystemRun）
- 関連: `docs/requirement/202609021050_タグ運用ガイドライン.md`, `docs/requirement/202609021102_タグ管理画面・タグ選択UI改修要件定義書.md`, ADR-0006, ADR-0008, ADR-0011, ADR-0061, ADR-0065, ADR-0070, ADR-0071

## 1. 目的

タグの同義語（`tag_alias`）を、タグ管理画面（`TagTreePage`）およびCSV一括インポート/エクスポートから、担当者自身が追加・編集・削除できるようにする。これにより、タグ運用ガイドライン（202609021050）5章・7章が前提とする「表記ゆれの語を`add_tag_alias`でエイリアスとして追加する」「片方を正、もう片方をエイリアスとして統合する」という運用を、管理画面から実際に遂行できる状態にする。

## 2. 背景

現状、`tag_alias`テーブル・関連するKnowledge MCPのツール（`add_tag_alias`/`remove_tag_alias`）自体はADR-0006の時点で用意されているが、次の理由により実質的に使えない状態にある。

- `web_backend`の`/api/tags`（`tag_controller.py`）は、`list_tags`/`create_tag`/`rename_tag`/`set_tag_description`/`move_tag`/`delete_tag`等はラップしているが、`add_tag_alias`/`remove_tag_alias`を呼び出すエンドポイントを持たない。
- `front_dev`の`TagTreePage`は、エイリアスを`title="同義語（表示のみ）"`として一覧表示・検索絞り込み（ADR-0070）・類似候補提示（ADR-0071）にのみ使い、追加・削除・編集の操作UIを持たない。
- エイリアス文字列自体を書き換える「編集」用のツール（`update_tag_alias`相当）は、Knowledge MCP側にもそもそも存在しない。
- タグCSV一括インポート（ADR-0061）・CSVエクスポート（ADR-0065）は、いずれも意図的に`tag_alias`を対象外としている（ADR-0065決定3: 「往復整合性を優先し、エイリアスは対象外とした」）。

このため現状、エイリアスを実際に追加・削除できる経路は、DBへの直接投入（`db_hiroba_qa_init/src/seed_description_and_aliases.py`、暫定シードと明記）か、Knowledge MCPツールをMCPクライアントから直接呼び出すか、の2つに限られており、いずれも運用担当者が日常的なタグ整理業務の中で使える手段ではない。

## 3. 用語

| 用語 | 説明 |
|---|---|
| エイリアス（`tag_alias`） | タグに登録された同義語・表記ゆれの語。`tag_alias(id, tag_id, alias)`、`alias`列はDB全体でUNIQUE。 |
| 類似候補チェック | ADR-0071で新設された、タグ新規作成時に入力名と既存タグ名・エイリアスとの類似性を非ブロッキングで警告する機能。 |

## 4. スコープ

### 4.1 対象範囲

1. `TagTreePage`に、タグごとのエイリアス追加・編集・削除UIを追加する。
2. Knowledge MCPに`update_tag_alias`ツールを新設し、既存の`add_tag_alias`/`remove_tag_alias`とあわせてエイリアスのCRUDを揃える。
3. `web_backend`の`/api/tags`に、エイリアス操作用のエンドポイントを追加する。
4. タグCSV一括インポート（ADR-0061）・CSVエクスポート（ADR-0065）に、エイリアス列を追加する（ADR-0065決定3の見直し）。
5. タグ新規作成時の類似候補チェック（ADR-0071）と同じロジックを、エイリアス追加・編集時にも適用する。

### 4.2 対象外

- タグ名・タグフォルダのCRUD自体（`create_tag`/`rename_tag`/`move_tag`/`delete_tag`/タグフォルダ関連）には変更を加えない。
- タグ管理全般の権限・承認フローの新設（ADR-0006のOpen Issueのまま。今回の機能も既存のタグCRUDと同じ「権限制御なし・operation logのみ記録」という扱いを踏襲する。本セッションで確認済み）。
- エイリアスを用いた検索・タグ選択ロジック自体（`tag_selector_mcp`の`RetrievalEngine`、`search_knowledge`のタグ類似度計算）の変更。エイリアスの追加・編集・削除が可能になった結果、`tag_selector_mcp`側のキャッシュ（ADR-0011、起動時ロード＋明示的リロード＋定期ポーリング）に反映されるまでの間、新しいエイリアスが`select_tags`のヒントとして即座には効かない場合があるが、これは既存のキャッシュ方針どおりの挙動であり、本書では変更しない。
- `TagPicker`（QA編集フォームでのタグ選択UI）へのエイリアス操作UI追加。エイリアス管理は`TagTreePage`（タグ管理画面）に閉じる。

## 5. 全体アーキテクチャ

```
front_dev/TagTreePage.tsx  … エイリアス追加・編集・削除UI、CSVインポート/エクスポートUI（列追加）
        │ HTTP: /api/tags/{tag_id}/aliases, /api/tags/{tag_id}/aliases/{alias_id}
        ▼
web_backend/tag_controller.py  … MCPツール呼び出し＋operation log記録のみ（薄いBFF、ADR-0013）
        │ MCP: add_tag_alias / update_tag_alias（新設） / remove_tag_alias
        ▼
knowledge_mcp/TagRepository, tag_alias テーブル
```

## 6. 機能要件

### 6.1 タグ管理画面でのエイリアス追加・編集・削除（`TagTreePage`）

- 各タグ行のエイリアス表示（`node.aliases`）を、表示のみのバッジから、次を備えたUIに変更する。
  - 追加: タグ行またはタグ詳細に「エイリアス追加」用の入力欄＋ボタンを設け、`add_tag_alias(tag_id, alias)`を呼ぶ。
  - 編集: 各エイリアスバッジをクリックすると文字列を編集できるようにし（インライン編集、または`window.prompt`— 既存の`rename_tag`と同水準の簡易UIでよい）、`update_tag_alias(alias_id, new_alias)`（6.2節で新設）を呼ぶ。
  - 削除: 各エイリアスバッジに削除ボタン（×）を設け、`remove_tag_alias(alias_id)`を呼ぶ。
- 追加・編集ともに、alias文字列が既存の別のエイリアスと重複する場合は、DBのUNIQUE制約に基づくエラー（`TagError`）をそのまま画面にエラー表示する（`create_tag`の重複エラー表示と同じパターン）。
- 6.4節の類似候補チェックを、この追加・編集の入力欄にも適用する。

### 6.2 Knowledge MCPツール（`update_tag_alias`の新設）

- 新規ツール`update_tag_alias(alias_id: int, new_alias: str) -> dict`を`knowledge_mcp`に追加する。`TagRepository.update_tag_alias`は次を行う。
  1. `alias_id`が存在しない場合は`TagError`。
  2. `new_alias`が、自分自身以外の既存エイリアスと重複する場合は`TagError`（`add_tag_alias`と同じ重複エラーメッセージ形式）。
  3. `UPDATE tag_alias SET alias = %s WHERE id = %s`を実行し、`{"id": alias_id, "tag_id": tag_id, "alias": new_alias}`を返す。
- 既存の`add_tag_alias`/`remove_tag_alias`のシグネチャ・挙動は変更しない。

### 6.3 web_backend API（`/api/tags`拡張）

`tag_controller.py`に次のエンドポイントに相当する処理を追加する（既存の`create_tag`/`update_tag`と同じ、MCPツール呼び出し＋`log_admin_operation`記録のみの薄い変換）。

| 操作 | 呼び出すMCPツール | operation log種別 |
|---|---|---|
| エイリアス追加 | `add_tag_alias(tag_id, alias)` | `create` / `tag_alias` |
| エイリアス編集 | `update_tag_alias(alias_id, new_alias)` | `update` / `tag_alias` |
| エイリアス削除 | `remove_tag_alias(alias_id)` | `delete` / `tag_alias` |

URLパスの`tag_id`はUI上の文脈（どのタグの操作か）を表すためのものであり、`update_tag_alias`/`remove_tag_alias`自体は`alias_id`のみで一意に解決できるため、MCP呼び出しには使わない。

### 6.4 エイリアス追加・編集時の重複・類似候補チェック（ADR-0071の拡張）

- ADR-0071で実装された`findSimilarTags`（`front_dev/src/feature/tag_admin/tagFilter.ts`）を、タグ新規作成の名前入力欄だけでなく、エイリアスの追加・編集の入力欄にも適用する。
- 対象タグ自身の名前・他のエイリアスとの一致は候補から除外する（同じタグの表記ゆれ追加は当然の操作であり、警告対象ではないため）。
- 別タグの名前・エイリアスと部分一致または編集距離が閾値以下の場合、ADR-0071と同じ非ブロッキングの警告（候補の名前・説明文・所属階層を表示）を出す。追加・編集操作自体はブロックしない。

### 6.5 タグCSV一括インポート/エクスポートへのエイリアス列追加（ADR-0061/0065決定3の見直し）

- CSV列に`aliases`列を追加する（`name`, `parent_name`, `description`, `aliases`の4列）。
- `aliases`列は、そのタグに登録されている複数のエイリアスをパイプ`|`区切りで1セルにまとめた文字列とする（例: `積算|歩掛|見積`）。
- **インポートは追加専用（additive-only）とする**。CSVの`aliases`列に列挙された各文字列のうち、対象タグにまだ登録されていないものだけを`add_tag_alias`で登録する。CSVに列挙されていない既存のエイリアスを削除する処理は行わない（タグ本体の一括インポートが既存タグを削除しない方針（ADR-0061）と揃える）。
- CSV内の1つのエイリアス文字列が、別のタグに既に登録済み（DBのUNIQUE制約に抵触）の場合、そのエイリアス1件だけをエラーとして行結果に記録し、タグ本体の作成・更新や他のエイリアスの登録は継続する（行単位のエラー許容という既存方針（ADR-0053/0061）を、行の中のエイリアス単位にも広げる）。
- エクスポートは、`export_tags`ツールが返す各タグレコードに`aliases`（文字列配列）を追加し、`web_backend`側でパイプ区切りに変換してCSVへ出力する。
- 詳細な実装方式・代替案の検討はADR-0081に記載する。

## 7. データ要件

- `tag_alias`テーブルのスキーマ変更は不要（既存の`id`/`tag_id`/`alias`のみで足りる）。
- `TagImportRowResult`（`web_backend/src/main/controllers/tag_controller.py`）に、エイリアス単位のエラーを表現するための項目（例: `alias_warnings: list[str] | None`）を追加する。

## 8. 非機能要件

- 権限制御は新設しない。既存のタグCRUD（`create_tag`等）と同じく、`log_admin_operation`による操作ログの記録のみを行う（ADR-0006 Open Issueをそのまま踏襲する、本セッションで確認済み）。
- `tag_selector_mcp`側のタグ知識ベースキャッシュ（ADR-0011）の即時反映は本書のスコープ外とする（4.2節）。

## 9. 影響範囲・互換性

- 影響を受けるコンポーネント: `knowledge_mcp`（`update_tag_alias`新設、`export_tags`/`import_tag_batch`の`aliases`対応）、`web_backend`（`tag_controller.py`のエンドポイント追加・CSV列追加）、`front_dev`（`TagTreePage.tsx`のエイリアスUI・CSV列追加）。
- 影響を受けないコンポーネント: `tag_selector_mcp`（`RetrievalEngine`のロジックは変更しない。キャッシュ経由で新しいエイリアスを参照するのみ）、`search_knowledge`のスコアリングロジック（ADR-0058/0059、エイリアスは元々不参照）。
- 既存のCSVインポート/エクスポート（`aliases`列を持たない古い形式のCSV）は、`aliases`列を省略可能な任意列として扱うことで引き続き利用できるようにする（後方互換）。

## 10. 受け入れ基準（Definition of Done）

- [ ] `TagTreePage`の各タグ行から、エイリアスの追加・編集・削除ができる。
- [ ] 追加・編集で他のエイリアスと重複する文字列を指定すると、エラーが表示され登録されない。
- [ ] 追加・編集時、別タグの名前・エイリアスと類似する文字列を入力すると、ADR-0071と同様の非ブロッキング警告が表示される（対象タグ自身の名前・エイリアスとの一致は警告されない）。
- [ ] タグCSVエクスポートに`aliases`列が追加され、複数エイリアスがパイプ区切りで出力される。
- [ ] `aliases`列を含むCSVを再インポートすると、まだ登録されていないエイリアスのみが追加され、既存のエイリアスは変化しない。
- [ ] CSV内のエイリアスが別タグと重複する場合、そのエイリアスのみがエラーとして報告され、タグ本体・他のエイリアスの処理は継続する。
- [ ] `aliases`列を持たない旧形式のCSVも、引き続きエラーなくインポートできる。

## 11. Open Issues

1. **エイリアス編集・削除の権限**: 4.2節のとおり本書では既存のタグCRUDと同じ扱い（権限制御なし）とするが、ADR-0006が残した「タグ管理全般の権限」Open Issueは未解消のまま引き継がれる。
2. **パイプ`|`を含む文字列のエイリアス登録**: CSVの区切り文字にパイプを採用したため、エイリアス文字列自体にパイプを含む場合の扱いは本書のMVPでは考慮しない（実運用で必要になった場合にエスケープ方式を別途検討する）。
3. **編集操作のUI形式**: 6.1節では簡易UI（インライン編集または`window.prompt`相当）を想定しているが、詳細設計時に決定する。
4. **`tag_selector_mcp`のキャッシュへの即時反映**: 4.2節のとおり本書では扱わないが、運用上「エイリアスを追加してもすぐに`select_tags`に反映されない」という体験上の分かりにくさが実際に問題になった場合、別途要件化を検討する。

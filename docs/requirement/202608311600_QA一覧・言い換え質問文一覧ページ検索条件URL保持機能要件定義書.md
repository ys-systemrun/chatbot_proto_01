# QA一覧・言い換え質問文一覧ページ 検索条件・ページ位置のURL保持機能 要件定義書

- 文書番号: REQ-202608311600
- 対象プロジェクト: chatbot_invitro
- 対象コンポーネント: `front_dev`（`QaListPage.tsx`, `QuestionAlteredListPage.tsx`, `QaFormPage.tsx`, `QuestionAlteredFormPage.tsx`）
- 変更なしのコンポーネント: `knowledge_mcp`, `web_backend`（既存API `GET /api/qa` / `GET /api/question_altered` の仕様はそのまま利用）、DBスキーマ、`tag_selector_mcp`, `agent_invitro`、`TagPicker.tsx` / `QaPicker.tsx` / `api.ts`（`api.ts`は既存の`getQa`を新たな箇所から呼び出すのみで、シグネチャ変更はない）
- 参照資料: `docs/requirement/202608060826_QAタグ管理UI要件定義書.md`、`docs/requirement/202608271750_言い換え質問文（question_altered）管理機能要件定義書.md`、`docs/requirement/202608311540_QAレコード削除機能要件定義書.md`、`docs/adr/0015-front-dev-admin-routing.md`、`docs/adr/0064-question-altered-management-via-knowledge-mcp.md`、`docs/adr/0067-qa-record-deletion-cascade.md`
- 前提の決定事項: 本書末尾「12. 関連ADR一覧」参照

## 1. 目的

QA一覧ページ（`QaListPage`）および言い換え質問文一覧ページ（`QuestionAlteredListPage`）について、キーワード・カテゴリ・タグ・対象QA等の検索条件と現在のページ位置をURLのクエリパラメータへ反映できるようにする。これにより、

1. 検索条件・ページ位置を含むURLを直接開く／リロードする／ブックマークする／他者に共有することで、同じ検索結果を再現できるようにする。
2. 一覧ページから各行の編集ページ（またはフォーム新規作成ページ）へ遷移し、保存・削除・キャンセルして一覧ページへ戻ってきた際に、遷移前の検索条件・ページ位置を保持したまま一覧を再表示できるようにする。

## 2. 背景・現状の課題

### 2.1 現状の実装

`QaListPage.tsx`は、検索条件（`keyword`, `category`, `tagIds`）とページ位置（`offset`）のすべてを`useState`によるコンポーネントローカルなstateとしてのみ保持している。URLは常に固定パス`/admin/qa`のみであり、これらのstateを一切反映しない。`QuestionAlteredListPage.tsx`も同様に、`keyword`, `qaId`, `qaLabel`, `offset`をローカルstateとしてのみ保持し、URLは固定パス`/admin/question_altered`のみである。

両ページとも、検索条件の変更やページ送りは、いずれも画面内の`load(nextOffset)`関数を呼び出すことで実現している。この関数は、その時点のローカルstateを読み取って`listQa`／`listQuestionAltered`（`api.ts`）を呼び出し、結果をstateへ反映するのみであり、URLへは一切書き込まない。

### 2.2 課題：編集ページへの遷移で検索条件・ページ位置が失われる

`routes.tsx`のルート定義は、`/admin/qa`（一覧）、`/admin/qa/:id`（編集）、`/admin/qa/new`（新規作成）をそれぞれ独立したルートとして`react-router-dom`（`react-router-dom` 6.26、ADR-0015で導入）で管理している。一覧ページから編集ページへ`Link`（例: `<Link to={\`/admin/qa/${qa.id}\`}>編集</Link>`）で遷移すると、一覧ページのコンポーネントはアンマウントされ、内部の`useState`はすべて破棄される。

`QaFormPage.tsx`は、保存成功後・削除成功後のいずれも`navigate("/admin/qa")`で固定パスへ遷移する（クエリパラメータを一切含まない）。また、画面上部の「← 一覧へ戻る」リンクも`<Link to="/admin/qa">`という固定パスである。この結果、たとえば「カテゴリ『料金』で絞り込み、2ページ目を表示していた」利用者が、その中の1件を編集して保存すると、一覧ページは検索条件なし・1ページ目の状態で再表示されてしまい、利用者は同じ検索条件・ページを毎回手動で再現する必要がある。`QuestionAlteredListPage.tsx`⇔`QuestionAlteredFormPage.tsx`の間にも、まったく同じ構造の課題が存在する（`QuestionAlteredFormPage.tsx`も`navigate("/admin/question_altered")`固定）。

### 2.3 前提となる既存基盤

- `react-router-dom`（6.26系）は、`/admin`配下のサブツリーに限定してADR-0015により既に導入済みである。`useSearchParams`フックによるクエリパラメータの読み取り・書き込みは、追加の依存パッケージなしに利用できる。
- `api.ts`の`listQa`は、`keyword` / `category` / `tag_id`（配列、`URLSearchParams.append`による繰り返しパラメータ）/ `limit` / `offset`をそのままAPIのクエリパラメータ名として使用している。`listQuestionAltered`も同様に、`qa_id` / `keyword` / `limit` / `offset`を使用している。本書が新設するURLクエリパラメータ名は、このAPI側のパラメータ名と極力一致させ、変換の手間を最小化する（4章・6.5節参照）。

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| 検索条件 | QA一覧における`keyword` / `category` / `tag_id`（複数可）、言い換え質問文一覧における`keyword` / `qa_id`の総称 |
| ページ位置 | 一覧の現在の表示ページ。内部実装では`offset`（0始まり、`PAGE_SIZE=20`固定）で管理されるが、本書ではURL上は`page`（1始まり）で表現する（6.5節） |
| URL同期 | 検索条件・ページ位置の変化を、`useSearchParams`によりブラウザのURLクエリパラメータへ反映すること |
| 履歴のreplace / push | ブラウザの操作履歴（History API）への反映方式。`replace`は現在の履歴エントリを置き換える（「戻る」で1つ前の別ページへ直接戻る）、`push`は新しい履歴エントリを追加する（「戻る」で1操作ずつ遡る） |
| `back`パラメータ | 編集ページ・新規作成ページのURLに付与する、遷移元の一覧ページのURL（パス＋クエリ文字列）をエンコードして格納する新規クエリパラメータ |
| ラベル解決 | 言い換え質問文一覧ページで、URLの`qa_id`から対象QAのタイトル（画面表示用の`qaLabel`）を`getQa` APIで取得すること |

## 4. スコープ

### 4.1 対象範囲（MVP）

- **QA一覧ページ（`QaListPage`）**: `keyword` / `category` / `tag_id`（複数可）/ `page`をURLクエリパラメータへ反映・復元する。
- **言い換え質問文一覧ページ（`QuestionAlteredListPage`）**: `keyword` / `qa_id` / `page`をURLクエリパラメータへ反映・復元する。`qa_id`が指定されている場合、対象QAのタイトル（`qaLabel`表示用）を`getQa`で解決する。
- 検索条件変更・ページ送り・削除後の再読込・CSVインポート後の再読込によるURL更新は、いずれもブラウザ履歴を**置き換える（replace）**。新しい履歴エントリは積まない（発注者確認済み、13章参照）。
- 一覧ページから編集ページ（`/admin/qa/:id`, `/admin/question_altered/:id`）・新規作成ページ（`/admin/qa/new`, `/admin/question_altered/new`）への遷移リンクに、遷移元一覧の現在のURL（パス＋クエリ文字列）を`back`クエリパラメータとして**明示的に**付与する（発注者確認済み、13章参照）。
- 編集・新規作成ページの「一覧へ戻る」リンク、および保存成功後・削除成功後の遷移先を、`back`パラメータの値（有効な場合）に切り替える。`back`が存在しない、または想定外の値の場合は、既存の固定パス（`/admin/qa`, `/admin/question_altered`）へフォールバックする。
- ページネーションのURL表現は`page`（1始まり）とする（発注者確認済み、13章参照）。内部の`offset`（0始まり、`PAGE_SIZE=20`固定）との相互変換はフロントエンド内で完結させる。
- タグ複数選択（QA一覧の`tag_id`）は、繰り返しパラメータ（例: `tag_id=3&tag_id=7`）で表現する（発注者確認済み、13章参照）。

### 4.2 対象外（将来検討・別スコープ）

- **名前付き検索条件の保存機能**: URLをブックマーク・共有することで実質的に同等の効果が得られるため、検索条件に名前を付けて保存するUI等の追加機能は本書では対象外とする。
- **`<details>`要素の開閉状態のURL反映**: タグ絞り込みパネル・CSVインポートパネルの展開／折りたたみ状態は、検索条件そのものではない画面上の表示状態として扱い、URLには反映しない。
- **タグ絞り込みの即時検索反映化**: 現状、`TagPicker`のチェック操作は`<form>`の外側にあり、「検索」ボタンを押すまで一覧に反映されない（既存仕様）。本書はこの既存挙動を変更しない。
- **ページサイズ（`PAGE_SIZE=20`固定）のURLでの可変化**: 対象外。
- **他の一覧系画面（タグ階層ページ`TagTreePage`、検証機能一覧`VerificationListPage`、エクスポートページ`ExportPage`）への同様のURL永続化の適用**: 本書はQA一覧・言い換え質問文一覧の2画面に限定する。他画面への適用は、要望が出た場合に別途要件化する（11章 Open Issue参照）。
- **`knowledge_mcp` / `web_backend` / DBスキーマの変更**: 一切発生しない。既存の`GET /api/qa` / `GET /api/question_altered`のリクエスト・レスポンス仕様は変更しない。

## 5. 全体アーキテクチャ

### 5.1 方式概要

```
QaListPage / QuestionAlteredListPage
  ├─ マウント時:
  │     useSearchParams() でURLを読み取り、初期state（keyword/category/tagIds/qaId、
  │     および offset = (page - 1) * PAGE_SIZE）を復元してから load(初期offset) を呼ぶ。
  │     不正・未指定の値は既定値（空文字列／空配列／page=1）にフォールバックする。
  │
  ├─ load(nextOffset) 実行時（初期表示・検索ボタン押下・ページ送り・
  │  削除後の再読込・CSVインポート後の再読込のすべてで共通に通る単一箇所）:
  │     1. 既存どおり listQa / listQuestionAltered を呼び出す
  │     2. 現在の検索条件と nextOffset から導出した page を用いて
  │        setSearchParams({ ...検索条件, page }, { replace: true }) を呼び、
  │        URLを常に表示内容と一致させる（既定値のパラメータはURLから省略する）
  │
  └─ 各行の「編集」リンク・「＋ 新規」リンク:
        to={`/admin/qa/${id}?back=${encodeURIComponent(location.pathname + location.search)}`}
        （言い換え質問文一覧側も同様のパターンを /admin/question_altered に適用する）

QaFormPage / QuestionAlteredFormPage
  ├─ useSearchParams() で自身のURLの `back` パラメータを取得する
  ├─ back の値が「/admin/qa」（または「/admin/question_altered」）で始まる相対パスの
  │  場合のみ有効な戻り先として採用する。それ以外（未指定・不正値）は、
  │  既存の固定パス（/admin/qa, /admin/question_altered）にフォールバックする
  └─ 上記で決定した戻り先を、「一覧へ戻る」リンクの遷移先、および
     保存成功後・削除成功後の navigate() の遷移先として使用する
```

### 5.2 コンポーネント一覧と責務（変更分）

| コンポーネント | 変更内容 |
|---|---|
| `front_dev`（`QaListPage.tsx`） | `keyword` / `category` / `tag_id` / `page`のURL同期（読み取り・書き込み）、「編集」「＋ 新規QA」リンクへの`back`パラメータ付与 |
| `front_dev`（`QuestionAlteredListPage.tsx`） | `keyword` / `qa_id` / `page`のURL同期、`qa_id`指定時の`getQa`によるラベル解決、「編集」「＋ 新規言い換え」リンクへの`back`パラメータ付与 |
| `front_dev`（`QaFormPage.tsx`） | `back`パラメータの読み取り・検証、「一覧へ戻る」リンク・保存/削除後の遷移先への反映 |
| `front_dev`（`QuestionAlteredFormPage.tsx`） | 同上（`/admin/question_altered`に対して） |

| `front_dev`（`api.ts`） | 変更なし。`QuestionAlteredListPage.tsx`が既存の`getQa`（現在は`QaFormPage.tsx`が利用中）を新たに呼び出すのみ |

## 6. 機能要件

### 6.1 QA一覧ページ（`QaListPage`）

- URLクエリパラメータ: `keyword`（string, 任意）, `category`（string, 任意, カテゴリ名をそのまま格納。既存の`category` stateおよび`listQa`の`category`パラメータと同一の値域）, `tag_id`（number, 複数可, 任意）, `page`（number, 任意, 1始まり, 既定値1）。
- マウント時、上記をURLから読み取り初期state化したうえで`load(初期offset)`を呼ぶ。`page`が数値でない・1未満等の不正値の場合は1として扱う。
- `load(nextOffset)`実行時（初期表示・「検索」ボタン押下・「前へ／次へ」ボタン・削除後の再読込・CSVインポート後の再読込のすべてに共通）、現在の検索条件と`nextOffset`から導出した`page`を用いて`setSearchParams({ ...条件, page }, { replace: true })`を呼び、URLを常に画面表示と一致させる。既定値（空文字列・空配列・`page=1`）に該当するパラメータはURLから省略し、URLを簡潔に保つ。
- 各行の「編集」リンク（`to="/admin/qa/{id}"`）、および「＋ 新規QA」リンク（`to="/admin/qa/new"`）に、現在のURL（`location.pathname + location.search`）を`encodeURIComponent`した`back`クエリパラメータを付与する。

### 6.2 言い換え質問文一覧ページ（`QuestionAlteredListPage`）

- URLクエリパラメータ: `keyword`（string, 任意）, `qa_id`（string/uuid, 任意）, `page`（number, 任意, 1始まり, 既定値1）。
- マウント時、`qa_id`がURLに存在する場合、画面上の「絞り込み中: {qaLabel}」表示のため、既存の`getQa(qa_id)`（`QaFormPage.tsx`で利用中のAPI関数を流用、`api.ts`の変更は不要）を呼び出してタイトルを取得する。取得に失敗した場合（対象QAが存在しない・削除済み等。ADR-0067参照）は、`qaLabel`を「（不明なQA。削除された可能性があります）」等のプレースホルダ表示とし、`qa_id`による絞り込み自体は維持する（一覧APIには引き続き`qa_id`を渡す。該当QAが実在しないため結果は0件になるが、これはDBの実状態を正しく反映した結果であり許容する）。
- `load()`実行時のURL同期・`back`パラメータ付与の方式は6.1節と統一する。

### 6.3 QA編集ページ（`QaFormPage`）からの一覧への復帰

- 自身のURLの`back`クエリパラメータを`useSearchParams`で読み取る。
- 値が`/admin/qa`で始まる相対パス（`/admin/qa`単体、または`/admin/qa?...`の形）である場合のみ、有効な戻り先として採用する。未指定・他ホストを指す値・`/admin/qa`以外のパスを指す値等は無効とみなし、既存の固定パス`/admin/qa`にフォールバックする（7章 非機能要件も参照）。
- 「← 一覧へ戻る」リンク（現状`<Link to="/admin/qa">`）の遷移先を、上記で決定した戻り先に置き換える。
- 保存成功後（`navigate("/admin/qa")`）・削除成功後（`navigate("/admin/qa")`）の遷移先を、同様に決定した戻り先に置き換える。

### 6.4 言い換え編集ページ（`QuestionAlteredFormPage`）からの一覧への復帰

6.3節と同様の方式を、対象パス`/admin/question_altered`に対して適用する。なお、`QuestionAlteredFormPage`が持つ「対象QA」への`Link`（`to={\`/admin/qa/${qaId}\`}`、関連QAの編集ページへ向かう別方向のリンク）は、一覧への「戻り」ではなく別画面への「進み」であるため、本書の対象外（`back`パラメータの付与対象としない）とする。

### 6.5 URLクエリパラメータ仕様一覧

| 画面パス | パラメータ | 型 | 必須 | 既定値 | 備考 |
|---|---|---|---|---|---|
| `/admin/qa` | `keyword` | string | 任意 | なし（省略） | `listQa`の`keyword`にそのまま渡す |
| `/admin/qa` | `category` | string | 任意 | なし（省略） | カテゴリ名。`listQa`の`category`にそのまま渡す |
| `/admin/qa` | `tag_id` | number（繰り返し） | 任意 | なし（省略） | 例: `tag_id=3&tag_id=7`。`listQa`の`tag_id`（配列）に変換して渡す |
| `/admin/qa` | `page` | number（1始まり） | 任意 | `1` | `offset = (page - 1) * 20` に変換して`listQa`へ渡す |
| `/admin/question_altered` | `keyword` | string | 任意 | なし（省略） | `listQuestionAltered`の`keyword`にそのまま渡す |
| `/admin/question_altered` | `qa_id` | string（uuid） | 任意 | なし（省略） | `listQuestionAltered`の`qa_id`にそのまま渡す。ラベル解決に`getQa`を追加利用 |
| `/admin/question_altered` | `page` | number（1始まり） | 任意 | `1` | `offset = (page - 1) * 20` に変換して`listQuestionAltered`へ渡す |
| `/admin/qa/:id`, `/admin/qa/new` | `back` | string（URLエンコード済み相対パス） | 任意 | なし（省略時は`/admin/qa`固定） | 一覧側で自動付与。`/admin/qa`で始まる値のみ有効 |
| `/admin/question_altered/:id`, `/admin/question_altered/new` | `back` | string（URLエンコード済み相対パス） | 任意 | なし（省略時は`/admin/question_altered`固定） | 一覧側で自動付与。`/admin/question_altered`で始まる値のみ有効 |

### 6.6 ブラウザ履歴（history）の扱い

- 一覧ページ内での検索条件変更・ページ送り・削除後の再読込・CSVインポート後の再読込によるURL更新は、いずれも履歴を**置き換える**（`setSearchParams(..., { replace: true })`）。新しい履歴エントリは積まない。
- 一覧ページへの初回遷移（グローバルナビ・管理ナビからのクリック、直接URL入力）、および編集ページ⇔一覧ページ間の遷移（`Link`によるページ遷移、保存・削除成功後の`navigate`）は、通常の遷移として履歴に積む（既存の`react-router-dom`標準動作のまま変更しない）。
- 結果として、一覧ページで検索条件を何度変更しても、ブラウザの「戻る」ボタンは一覧に入る前のページ（管理メニュー等）へ1回の操作で直接戻る。

## 7. 非機能要件

| 分類 | 要件 |
|---|---|
| オープンリダイレクト対策 | `back`パラメータは利用者が編集可能なURL値であるため、`/admin/qa`または`/admin/question_altered`で始まる相対パスのみを許可するホワイトリスト検証を行う。それ以外の値（他ホストを指す値、想定外のパス等）は無視し、既定の固定パスへフォールバックする |
| 後方互換性 | `back`パラメータを持たない既存のブックマーク・直接入力されたURL（例: `/admin/qa/{id}`のみ）は、これまで通り固定パスへの遷移で正しく動作する |
| 副作用なし | URLクエリパラメータの読み取り・書き込みはブラウザの表示状態のみに影響し、API呼び出しのリクエスト内容（既存の`GET /api/qa` / `GET /api/question_altered`のクエリパラメータ仕様）には変更を加えない |
| パフォーマンス | `setSearchParams`の呼び出しはブラウザ内の履歴操作のみであり、追加のネットワークリクエストは発生しない。言い換え質問文一覧の`qa_id`ラベル解決（`getQa`）は、URLに`qa_id`が含まれる場合のみマウント時に1回発生する追加リクエストである |
| アクセス制御 | 変更なし。既存の管理画面群と同様、ネットワークレベルの制限（社内IPアドレス限定、ADR-0041）のみとする |

## 8. インフラ・実行環境要件

追加のインフラ変更は想定しない。既存の`front_dev`ビルド・配信構成（ADR-0042）、docker-compose・AWS ECS Fargate構成をそのまま利用する。新規の環境変数・依存パッケージの追加はない（`react-router-dom` 6.26は既にADR-0015で導入済みであり、`useSearchParams`は追加インストールなしに利用可能）。

## 9. 既存システムとの関係・影響範囲

- `knowledge_mcp` / `web_backend` / DBスキーマへの変更は一切ない。既存の`GET /api/qa` / `GET /api/question_altered`のリクエスト・レスポンス仕様は変更しない。
- 変更対象は`QaListPage.tsx` / `QuestionAlteredListPage.tsx` / `QaFormPage.tsx` / `QuestionAlteredFormPage.tsx`のみ。`TagPicker.tsx` / `QaPicker.tsx`への変更は想定しない。`api.ts`は、`QuestionAlteredListPage.tsx`が既存の`getQa`関数を新たに呼び出す（インポートを追加する）のみで、関数シグネチャの変更はない。
- QAレコード削除機能（ADR-0067）との関係: QA削除により、言い換え質問文一覧ページの`qa_id`フィルタが指す先が失われる（ブックマーク・共有されたURL経由で再度開かれる）ケースが新たに顕在化しうる。6.2節のラベル解決フォールバック表示で対応する。
- タグ階層ページ（`TagTreePage`）・検証機能一覧ページ（`VerificationListPage`）・エクスポートページ（`ExportPage`）には変更を加えない。

## 10. 受け入れ基準（Definition of Done, MVP）

- [ ] QA一覧ページでキーワード・カテゴリ・タグ・ページを指定した状態でURLをコピーし、別タブで開く（またはリロードする）と、同じ検索条件・ページが再現される。
- [ ] 言い換え質問文一覧ページでキーワード・対象QA・ページを指定した状態でURLをコピーし、別タブで開く（またはリロードする）と、同じ検索条件・ページ（対象QAのラベル表示を含む）が再現される。
- [ ] QA一覧ページで検索条件・ページを指定した状態から、いずれかの行の「編集」リンクで編集ページへ遷移し、保存（または削除）すると、遷移前と同じ検索条件・ページ位置で一覧ページへ戻る。
- [ ] 「＋ 新規QA」から新規作成・保存した場合も、遷移前（新規作成前）の検索条件・ページ位置を保持して一覧ページへ戻る。
- [ ] 言い換え質問文一覧ページについても、編集・新規作成・削除の各操作後、遷移前の検索条件・ページ位置を保持して一覧ページへ戻る。
- [ ] 一覧ページ内で検索条件を複数回変更しても、ブラウザの「戻る」ボタンを1回押すと、一覧に入る前のページへ直接戻る（検索条件変更ごとの履歴が積み上がっていない）。
- [ ] `back`パラメータを持たない従来通りのURL（`/admin/qa/{id}`のみ等）を直接開いた場合も、「一覧へ戻る」・保存/削除後の遷移が既存の固定パスへ正しく遷移する（後方互換性）。
- [ ] `back`パラメータに不正な値（他ホストを指すURL等）を手動で与えても、既定の固定パスへフォールバックし、意図しない遷移先へ遷移しないことを確認する。
- [ ] 削除済みQAのUUIDを指す`qa_id`クエリパラメータで言い換え質問文一覧ページを開いた場合、画面がエラーにならず、フォールバック表示とともに一覧が（0件として）正しく表示される。
- [ ] 既存のQA一覧・言い換え質問文一覧の検索・ページング・タグ絞り込み・CSVインポート/エクスポート・削除の各機能の動作に影響がないことを確認する。

## 11. Open Issues（要追加確認事項）

1. **他一覧ページへの適用**: タグ階層ページ・検証機能一覧ページ・エクスポートページ等、他の一覧系画面にも同様のURL永続化を適用するかは本書のMVP対象外。要望が出た場合に別途要件化する。
2. **名前付き検索条件（保存済みフィルタ）機能の要否**: 現状はURLの共有・ブックマークで実質的に代替できるため本書では対象外とするが、運用開始後に要望が出た場合は別途検討する。
3. **タグ絞り込みの即時反映化**: 現状、タグのチェック操作は「検索」ボタン押下まで一覧に反映されない（4.2節・6.2節参照）。本書はこの既存挙動を変更しないが、UX改善の要望が出た場合は別途要件化する。
4. **`back`パラメータのURL長**: 検索条件が多い場合（タグを多数選択している場合等）、`back`パラメータの値が長くなり編集ページのURLが長大になる可能性がある。実用上問題になる可能性は低いと考えるが、運用開始後に問題が顕在化した場合は別途対応を検討する。

# 全データエクスポート機能 要件定義書

- 文書番号: REQ-202608241530
- 対象プロジェクト: chatbot_invitro
- 対象コンポーネント: `front_dev`（新規エクスポート画面）, `web_backend`（新規エクスポートAPI）, `db_hiroba_qa_init`（新規ロール作成）, `terraform/`（新規シークレット・環境変数）
- 参照資料: `docs/requirement/202608211014_AWS環境向けQAタグ管理UI要件定義書.md`, `docs/requirement/202608240949_AWS環境向けChatbotUI・会話評価機能有効化要件定義書.md`
- 前提の決定事項: 本書末尾「13. 関連ADR一覧」参照

## 1. 目的

本プロジェクトが保持する全ての業務データ（QAナレッジベース、タグ、会話履歴・評価データ）を、管理者がブラウザ上のボタンクリックのみで、SQLまたはCSV形式のファイルとしてダウンロードできる機能を追加する。

主な利用目的として、次を想定する。

1. 開発・検証環境間でのデータ移行（ローカル `docker-compose` 環境とAWS環境の間でのデータ確認・受け渡し）
2. AWS上のデータのアドホックなバックアップ（自動バックアップ・定期スナップショットとは別に、任意タイミングで手元にファイルとして保持したい場合）
3. QA・タグ・会話評価データの内容を、Excel等の表計算ソフトで確認・分析したい場合（CSV形式）

本書は、この機能の要件定義および設計判断（ADR）の整理を対象とし、コーディング自体は対象外とする。

## 2. 背景・参照資料

- QA・タグ管理UI（`front_dev` / `web_backend`）は、AWS環境向けにALB経由・社内IPアドレス限定でブラウザから到達できるようになっている（`docs/requirement/202608211014.md`、ADR-0041、ADR-0042）。本書の新機能も、この既存の `admin_ui` サービスに追加する画面・APIとして実現する。
- `chatbot_invitro` が扱う業務データは、同一のAmazon RDS for PostgreSQLインスタンス（`chatbot-invitro-rds`、ADR-0026）上の2つのデータベースに分かれている。
  - `chatbot` データベース: QA・タグ・埋め込みベクトル（`qa_original` / `question_altered` / `category` / `tag` / `tag_alias` / `qa_tag`）。書き込みはKnowledge MCPサーバ経由に統一されている（ADR-0013）。
  - `conversation` データベース: 会話履歴・評価データ（`conversation` / `message`）。`admin_ui`（`web_backend`）が直接読み書きする（ADR-0044、ADR-0045）。
- `admin_ui` は現状、`conversation` データベースへの直接アクセス資格情報（`CONVERSATION_DB_URL`）は保持するが、`chatbot` データベースへの直接アクセス資格情報は保持しない（ADR-0045）。本書が定義するエクスポート機能は、両方のデータベースの全テーブルを対象とするため、`chatbot` データベースに対する新たなアクセス経路の要否を検討する必要がある（→ ADR-0046）。

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| 全データ | 本書のスコープにおいては、`chatbot` データベースの6テーブル（`qa_original` / `question_altered` / `category` / `tag` / `tag_alias` / `qa_tag`）と、`conversation` データベースの2テーブル（`conversation` / `message`）を合わせた計8テーブルを指す。5章で対象外とするデータは含まない。 |
| エクスポート | 対象データベースの全テーブルの全行を、SQL形式（`INSERT`文を含むリプレイ可能なSQLファイル）またはCSV形式（テーブルごとの表形式ファイル）としてファイル化し、ブラウザにダウンロードさせる操作。 |
| admin_ui サービス | `front_dev` の本番ビルド資産と `web_backend` を配信する既存のECS Fargateサービス（ADR-0041、ADR-0042）。本書のエクスポート機能もこのサービスに追加する。 |

## 4. スコープ

### 4.1 対象範囲（MVP）

- `front_dev` の `/admin` 配下に、エクスポート専用ページ（`/admin/export`）を新設する。SQL/CSVの形式選択と、エクスポートを実行するボタンを設ける。
- `web_backend` に、対象8テーブルをSQLまたはCSVとして生成し、ZIPアーカイブとしてダウンロードさせるAPI（`GET /api/export`）を新設する。
- `chatbot` データベースに対する、エクスポート専用の読み取り専用アクセス経路を新設する（ADR-0046）。
- ローカル `docker-compose` 環境・AWS環境の両方で同一の機能を提供する（既存のQA・タグ管理UIと同様、ADR-0013の6.4節の考え方を踏襲）。

### 4.2 対象外（将来検討・別スコープ）

- データベース内の8テーブル以外のデータ（`data/` ディレクトリのシード素材ファイル、Terraform state、アプリケーションログ、Dockerボリューム内の生PostgreSQLクラスタファイル等）のエクスポート。本機能はアプリケーションが管理する業務データの8テーブルに限定する。
- エクスポートしたファイルの自動アーカイブ・世代管理・S3等への恒久保存（都度ブラウザへダウンロードするのみとし、サーバー側にファイルを残さない）。
- 定期実行・スケジュールエクスポート（本フェーズは利用者のボタン操作によるオンデマンド実行のみ）。
- インポート機能（エクスポートしたSQL/CSVを別環境に取り込む操作自体は本書の対象外とし、生成するSQLファイルが `psql -f` 等で再投入可能な形式であることの確認にとどめる）。
- アプリケーションレベルの追加認証・利用者ごとのアクセス権限分離（既存UIと同様、本フェーズは見送り。9章・12章参照）。
- テーブル単位・期間単位等の部分エクスポート（本フェーズは「全データ」の一括エクスポートのみとし、絞り込みは対象外とする）。

## 5. 全体アーキテクチャ

### 5.1 システム構成（追加分のみ抜粋）

```
ブラウザ（社内IPアドレスからのみ, ADR-0041）
        │
        ▼
┌─────────────────────────────────────────┐
│  admin_ui サービス（既存, ECS Fargate）              │
│  - front_dev: /admin/export ページ（新規）            │
│  - web_backend: GET /api/export（新規）              │
└───────────┬───────────────────┬─────────────┘
            │ 読み取り専用（新規, ADR-0046）      │ 既存（ADR-0044, 0045）
            ▼                               ▼
   chatbot データベース                conversation データベース
   （chatbot-invitro-rds上）           （chatbot-invitro-rds上）
```

- Knowledge MCPサーバ・Tag Selector MCPサーバ・agent_invitroの構成・ネットワーク境界（ADR-0023, 0013, 0043）には変更を加えない。
- `admin_ui` から `chatbot` データベースへの新規読み取り経路は、既存のQA・タグ書き込み経路（Knowledge MCP経由、ADR-0013）とは別系統とし、書き込み系のロジックには影響しない。

### 5.2 コンポーネント一覧と責務（追加・変更分）

| コンポーネント | 責務 |
|---|---|
| `front_dev`（`/admin/export`、新規） | 形式（SQL/CSV）選択UI、エクスポート実行ボタン、生成されたZIPファイルのダウンロード処理 |
| `web_backend`（`GET /api/export`、新規） | 対象8テーブルの読み取り、SQL/CSVの生成、ZIPアーカイブ化、HTTPレスポンスとしてのストリーミング配信 |
| `chatbot` データベース用エクスポート専用ロール（新規, ADR-0046） | `chatbot` データベース6テーブルへの読み取り専用アクセスを `admin_ui` に提供する |
| `db_hiroba_qa_init`（拡張） | エクスポート専用ロールの作成・権限付与（起動時、冪等） |

## 6. 機能要件

### 6.1 エクスポート画面（`/admin/export`）

- 「SQL」「CSV」のいずれかを選択するラジオボタン（初期選択はどちらか一方、詳細設計フェーズで確定）。
- 「エクスポート」ボタン。クリックすると `GET /api/export?format=sql` または `GET /api/export?format=csv` を呼び出す。
- 処理中はボタンを無効化し、多重クリックによる二重リクエストを防止する。
- 成功時はブラウザの標準的なファイル保存動作（ダウンロード）を発生させる。失敗時（後述のエラー時）は画面上にエラーメッセージを表示する。

### 6.2 エクスポートAPI（`GET /api/export`）

- クエリパラメータ `format`（`sql` または `csv`、必須）を受け付ける。
- `chatbot` データベース6テーブル・`conversation` データベース2テーブルの全行を読み取り、ZIPアーカイブを生成して返す（生成方式の詳細はADR-0047）。
  - CSV形式: テーブルごとに1ファイル、計8ファイル。`question_altered.csv` は `embedding` 列を含まない。
  - SQL形式: データベースごとに1ファイル（`chatbot.sql`, `conversation.sql`）、計2ファイル。`chatbot.sql` は `question_altered.embedding` を含む。各ファイルは `CREATE TABLE IF NOT EXISTS` と `INSERT INTO` 文で構成し、単体で `psql -f` により再投入可能な形式とする。
- レスポンスは `Content-Type: application/zip`、`Content-Disposition: attachment; filename=chatbot_invitro_export_<タイムスタンプ>_<format>.zip` とする。

### 6.3 対象外の操作

- 部分エクスポート（テーブル指定、期間指定等)、インポート、スケジュール実行は本機能に含めない（4.2節）。

## 7. データ要件

### 7.1 対象テーブル

| データベース | テーブル | 備考 |
|---|---|---|
| `chatbot` | `qa_original` | 質問・回答の原本データ |
| `chatbot` | `question_altered` | 言い換えパターン・埋め込みベクトル（`embedding`列） |
| `chatbot` | `category` | 問い合わせ分類 |
| `chatbot` | `tag` | タグマスタ（階層構造） |
| `chatbot` | `tag_alias` | タグの同義語 |
| `chatbot` | `qa_tag` | QAとタグの関連 |
| `conversation` | `conversation` | 会話セッション |
| `conversation` | `message` | 会話メッセージ・評価（good/bad） |

- スキーマの追加・変更は本書のスコープでは行わない。既存の `db_hiroba_qa_init`（ADR-0016〜0018）・`db_conversation/init.sql`（ADR-0044）で管理されているスキーマをそのまま対象とする。
- 将来テーブルが追加された場合、エクスポート機能・エクスポート専用ロールの権限（ADR-0046の `ALTER DEFAULT PRIVILEGES`）双方への追従が必要になる（12章Open Issue参照）。

## 8. 非機能要件

| 分類 | 要件 |
|---|---|
| アクセス制御（ネットワーク） | 既存のQA・タグ管理UIと同一のALB・社内IPアドレス限定（ADR-0041）をそのまま適用する。追加のネットワーク境界は設けない。 |
| アクセス制御（アプリケーション） | 追加のログイン認証は実装しない（既存UIと同一方針）。ただし「全データを一括で持ち出せる」操作は通常のQA閲覧・編集より機微度が高いため、将来的な認証・監査ログの要否を12章Open Issueとして残す。 |
| データベースアクセス権限 | `chatbot` データベースへのエクスポート用アクセスは、読み取り専用ロール（ADR-0046）に限定する。書き込み権限は付与しない。 |
| 性能 | 現時点のデータ規模（QAナレッジベース、会話評価ログ）を前提に、同期的なHTTPリクエスト・レスポンスで完結させる（ADR-0047）。明確な応答時間目標は設けないが、ALB・ブラウザのタイムアウト内に完了することを目安とする。 |
| 可用性 | 既存 `admin_ui` と同一（単一インスタンス構成、`desired_count=1`）。エクスポート機能専用の冗長化は行わない。 |
| ログ | エクスポートが実行された事実（日時、形式）をアプリケーションログに記録する。利用者個人の記録は、追加認証を実装していない現状では取得できないため対象外とする。既存のALBアクセスログ（送信元IPアドレス）と合わせて参照する。 |
| データの機微性 | `conversation`/`message` には利用者からの問い合わせ内容（個人情報を含み得る）が保存されている可能性がある。エクスポートしたファイルは利用者のローカル環境にダウンロードされるため、取り扱い（保管・共有範囲）については運用担当者への注意喚起を行う（12章Open Issue参照、ADR-0044の既存論点を引き継ぐ）。 |
| コスト | 新規のAWSリソース（ALB等）は発生しない。データベースロールの新設、`web_backend`・`front_dev`のコード追加のみであり、追加の稼働コストは実質的に発生しない。 |
| 保守性・拡張性 | エクスポート対象テーブルの定義（カラムリスト等）は、`web_backend` 内の設定として一箇所にまとめ、将来のスキーマ変更時に追従しやすい構成とする。 |

## 9. インフラ・実行環境要件

- `chatbot` データベースに読み取り専用ロール（`chatbot_export_reader`、仮称）を新設する（ADR-0046）。
- `terraform/modules/database` に `chatbot_export_db_url_secret_arn` を追加し、`admin_ui` の secrets に `CHATBOT_EXPORT_DB_URL` として伝播させる。
- `db_hiroba_qa_init` にロール作成・権限付与のステップを追加する（起動時、冪等）。
- 追加のセキュリティグループルールは不要（既存の `admin_ui_task → rds` ルール、ADR-0045を流用）。
- ローカル `docker-compose` 環境は、既存の `DATABASE_URL` / `CONVERSATION_DB_URL` をそのままエクスポート機能でも使用し、追加の環境変数・ロールは設けない（ADR-0046）。

## 10. 既存システムとの関係・影響範囲

- Knowledge MCPサーバ・Tag Selector MCPサーバ・agent_invitroには変更を加えない。
- QA・タグの登録・編集・削除（既存の書き込み経路、ADR-0013）には変更を加えない。エクスポート機能は読み取り専用の新規経路として追加する。
- `conversation`/`message` の直接アクセス（ADR-0044、ADR-0045）には変更を加えない。既存の `CONVERSATION_DB_URL` をエクスポートにも流用する。
- 既存のQA一覧・タグ階層・会話評価画面（`front_dev`）には影響しない。新規ページ（`/admin/export`）の追加にとどまる。

## 11. 受け入れ基準（Definition of Done, MVP）

- [ ] 社内IPアドレスからブラウザで `/admin/export` にアクセスし、SQL・CSVそれぞれの形式でエクスポートを実行できる。
- [ ] エクスポートされたZIPファイルに、`chatbot` データベース6テーブル・`conversation` データベース2テーブルの全行が含まれていることを確認する。
- [ ] SQL形式でエクスポートしたファイル（`chatbot.sql`, `conversation.sql`）を、まっさらなPostgreSQLに対して `psql -f` で実行し、エラーなく投入できることを確認する。
- [ ] CSV形式でエクスポートしたファイルが、Excel等の表計算ソフトで問題なく開けることを確認する。
- [ ] `chatbot` データベースへのエクスポート専用ロールが、`SELECT` 以外の操作（`INSERT`/`UPDATE`/`DELETE`/DDL）を実行できないことを確認する（データベース側の権限確認、またはロールでの接続による実操作確認）。
- [ ] 既存のQA・タグ登録編集機能、会話評価機能の動作に影響がないことを確認する。
- [ ] ローカル `docker-compose` 環境でも同様にエクスポートが実行できることを確認する。

## 12. Open Issues（要追加確認事項）

1. **将来的な認証・監査ログの要否**: 「全データを一括で持ち出せる」操作の機微度を踏まえ、社内IPアドレス限定に加えて追加のログイン認証・操作者記録が必要かどうかを発注者に確認する必要がある（既存UI要件定義書13章Open Issue #2、202608211014要件定義書12章Open Issue #6と同一線上の課題）。
2. **会話データの取り扱い方針**: `conversation`/`message` に個人情報・機微情報が含まれる場合の、エクスポートファイルの保管・共有・削除ルールを運用担当者向けに定める必要がある（ADR-0044のOpen Issue「会話データの保持期間・削除方針」と合わせて確認する）。
3. **データ量増加時の同期配信方式の限界**: `conversation`/`message` の保持期間ポリシーが未確定（ADR-0044）のまま長期間データが蓄積した場合、ADR-0047が採用した同期的なストリーミング配信ではALB・ブラウザのタイムアウトに抵触するリスクがある。データ量が一定規模を超えた場合、非同期ジョブ化・S3経由の配信方式への切り替えを別途検討する必要がある。
4. **CSV形式での埋め込みベクトルの要否**: 本書ではCSV形式から `embedding` 列を除外する方針としたが（ADR-0047）、分析目的で埋め込みベクトルそのものをCSVで扱いたいという要望が将来生じた場合、オプション化を別途検討する。
5. **将来のテーブル追加への追従**: 新しいテーブルが追加された場合、エクスポート対象定義（7.1節）・エクスポート専用ロールの権限（ADR-0046の`ALTER DEFAULT PRIVILEGES`は自動追従するが、`web_backend`側のテーブル定義リストは手動更新が必要）の両方を更新する運用ルールを、実装フェーズで明文化する必要がある。

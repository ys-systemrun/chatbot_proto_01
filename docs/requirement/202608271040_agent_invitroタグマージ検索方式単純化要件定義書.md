# agent_invitroタグマージ検索方式単純化 要件定義書

- 日付: 2026-08-27
- ステータス: 確定
- 関連調査: `docs/detected_problems/202608270951_チャット情報源検索結果検証ページとの差異調査報告.md`

## 1. 目的

実チャット（`agent_invitro`の`POST /ask-sl`）における情報源検索（`search_knowledge`呼び出し）の方式を、検証機能（ADR-0060）と同一の「マージタグ全件を1回の`tags`引数で渡す」方式に単純化し、実チャットの情報源検索結果を検証ページと一致させる。

## 2. 背景・参照資料

- `docs/detected_problems/202608270951_チャット情報源検索結果検証ページとの差異調査報告.md`（本書の起点となった調査報告。根本原因の詳細分析を含む）
- ADR-0057（`agent_invitro`における会話タグの検索反映方式と継続タグ判定ロジック、2026-08-26）: 策定当時、`knowledge_mcp`の`search_knowledge`の`tags`引数が完全一致AND条件であったため、「マージタグ1件につき1回呼び出し＋タグ指定なしのフォールバック呼び出し1回＋結果をQA単位で最大スコア統合する」というワークアラウンド（`agent_invitro/src/tags.py`の`search_with_merged_tags`）を採用した。
- ADR-0058（祖先タグの動的展開）・ADR-0059（タグ構成類似度と埋め込み類似度を統合したスコアリング方式、2026-08-26）: `search_knowledge`の`tags`引数を、完全一致AND条件から「タグ類似度によるソフトなランキングシグナル」に変更した。これにより、ADR-0057が対応していた「タグ数が増えるほど検索結果が0件に近づくリスク」は解消された。
- `docs/requirement/202608261450_タグ階層展開・タグ構成類似度スコアリング機能要件定義書.md`12章 Open Issue #1: 「ADR-0057のワークアラウンドは単純化できる可能性が高いが、本書のスコープでは`agent_invitro`側の実装変更は行わず、要否・実施タイミングは別途判断する」と明記されていた課題。本書はこの課題への回答である。
- ADR-0060（検証機能への既存タグ入力パラメータ追加、2026-08-26）・`web_backend/src/main/controllers/verification_controller.py`: 検証機能は当初からマージタグ全件を1回の`search_knowledge`呼び出しで渡す方式（新スコアリング方式を前提とした実装）になっている。
- ユーザー確認結果（本書起票時点の対話）:
  - 事象は会話の1ターン目から発生する。
  - 判断根拠は、実チャットの回答内容が的外れであること、および同じ質問を検証ページに送ると正しく情報源を取得できることの比較。
  - ローカル環境での再現有無は未検証。
  - AWS環境では、この機能がリリースされた当初から一貫して情報源検索がうまく機能していないと見られる。

## 3. 現状の問題点（要約）

`agent_invitro/src/tags.py`の`search_with_merged_tags`は、マージタグ1件ごとに個別の`search_knowledge`呼び出し（各回、そのタグ単独の閉包に対するタグ類似度のみでスコア計算）に加え、タグ指定なしのフォールバック呼び出し（埋め込み類似度のみ）を行い、全結果をQA単位で「最大スコア」により統合する。これは、検証ページが行う「マージタグ全件を1回で渡した場合の、タグ集合全体に対する一体的なタグ類似度計算」とは異なる、かつ数学的に整合しないスコアの混在（タグ単独の類似度と、タグなしの埋め込み類似度が同じ尺度として最大値比較される）を生じさせ、実チャットの検索結果が検証ページの結果より劣化・不一致になっている。

この問題は会話の蓄積（継続タグ判定ロジック）とは独立して、1ターン目から発生する（マージタグが1件以上あれば、タグ別呼び出し＋フォールバック呼び出しの計2回以上が常に行われ、単一呼び出しとは異なる統合結果になるため）。

## 4. スコープ

### 4.1 対象範囲（本書）

- `agent_invitro`の`search_knowledge`呼び出し方式を、マージタグ全件を1回の`tags`引数にまとめて渡す単一呼び出し方式に変更する（`agent_invitro/src/tags.py`の`search_with_merged_tags`の実装見直し、または同等の単純化）。
- タグ指定なしのフォールバック呼び出し（環境変数`TAG_SEARCH_FALLBACK_ENABLED`）は廃止する。ADR-0059により「`tags`引数が指定されない場合と空配列の場合は同じ扱い」となっているため、マージタグが0件のときも単一呼び出し（`tags=[]`）で従来のフォールバック相当の挙動（埋め込み類似度のみでの検索）が自然に得られ、別呼び出しを維持する理由がない。

### 4.2 対象外（本書のスコープ外）

- 継続タグ判定ロジック（ADR-0057 4節: `select_tags`の明示呼び出し、クライアント由来タグとのマージ、`missed_turns`によるしきい値判定）は変更しない。
- `tag_selector_mcp`・`knowledge_mcp`自体の変更は行わない（ADR-0058/0059で既に完了済みの範囲）。
- 検証機能（`web_backend`の`verification_controller.py`）の変更は行わない。
- 実チャットのフロントエンドUIに「情報源」を表示する機能の追加は本書のスコープ外とする（12章 Open Issueに記録し、別途要件として検討する）。
- ローカル`docker-compose`環境での再現検証は本書のスコープ外とする（12章 Open Issue参照）。

## 5. 変更後の仕様

### 5.1 `search_knowledge`呼び出しの単純化

`agent_invitro/src/tags.py`の`search_with_merged_tags`（またはこれを置き換える関数）を、次のように単一呼び出しに変更する。

```python
result = await search_tool.ainvoke({
    "query": query,
    "tags": [t.name for t in merged_tags],  # 0件でも [] のまま渡す
    "top_k": top_k,
})
return extract_results_fn(result)[:top_k]
```

- マージタグが0件の場合も同じ呼び出し（`tags=[]`）でよい（ADR-0059により`tags`未指定と同じ扱いになる）。
- `asyncio.gather`による並列呼び出し・QA単位の重複排除・最大スコア統合のロジックは不要になり削除する。

### 5.2 環境変数の扱い

- `TAG_SEARCH_FALLBACK_ENABLED`: 廃止する（`agent_invitro/src/config.py`の定義を削除し、`terraform/main/app/main.tf`の`module "agent_invitro"`の`environment`からも削除する）。
- `TAG_SELECTOR_MAX_TAGS`・`TAG_SELECTOR_CONFIDENCE_THRESHOLD`・`TAG_CONTEXT_MAX_TAGS`・`TAG_CONTEXT_MAX_MISSED_TURNS`: 継続タグ判定ロジックに使う値であり、変更しない。
- `top_k`（現状`main/api/server.py`にハードコードされた`3`）・`min_score`（現状未指定＝既定`0.0`）は本書では現状維持とし、検証ページの既定値（`top_k=5`・`min_score=0.0`）と揃えるかどうかは12章 Open Issueとして別途判断する。

### 5.3 ログ出力

既存のログ`search_with_merged_tags query=%r merged_tags=%d hits=%d`は、呼び出し回数の記述（「マージタグ別複数回呼び出し」の説明）を実態（単一呼び出し）に合わせて更新する。ログの意味（クエリ・マージタグ数・取得件数）自体は維持する。

## 6. 非機能要件

- レイテンシ改善: 1リクエストあたりの`search_knowledge`呼び出し回数が最大6回（既定値、ADR-0057）から1回に減る。ADR-0057の要件定義書12章 Open Issue #5（レイテンシへの影響計測）は本変更により実質的に解消される方向になる。
- 既存の継続タグ判定・会話要約ロジックへの影響がないこと。

## 7. 影響範囲

- `agent_invitro/src/tags.py`（`search_with_merged_tags`の実装変更、または廃止して呼び出し元に単一呼び出しを直接記述）
- `agent_invitro/src/main/api/server.py`（`_ask_impl`内の呼び出し部分・ログ出力の更新）
- `agent_invitro/src/config.py`（`tag_search_fallback_enabled`関連の定義削除）
- `terraform/main/app/main.tf`（`module "agent_invitro"`の`environment`から`TAG_SEARCH_FALLBACK_ENABLED`を削除）
- `agent_invitro/tests`配下の関連テスト（タグ別複数回呼び出し・フォールバック呼び出しを前提にしたテストケースの更新）
- `docs/adr/0057-agent-invitro-tag-merged-search-and-continuation-logic.md`（3節の決定を本書に基づくADR-0062により限定的に改訂）

## 8. 受け入れ基準（Definition of Done）

- 同一の質問文・同一のマージタグ集合を検証ページと実チャットの双方に与えたとき、`search_knowledge`から得られる上位`top_k`件の情報源（QA）が一致すること（`top_k`の値自体が異なる場合は、小さい方の`top_k`件の範囲で一致すること）。
- 会話の1ターン目から、検証ページと同等の情報源検索結果が得られること。
- 継続タグ判定ロジック（`missed_turns`の更新・破棄・上限間引き）の既存の振る舞いに変化がないこと。
- `TAG_SEARCH_FALLBACK_ENABLED`を参照していたテスト・設定が整理され、CI上のテストが通ること。

## 9. Open Issues（要追加確認事項）

1. **`top_k`・`min_score`の値統一**: 実チャットの`top_k`（現状3）を検証ページの既定値（5）に合わせるか、現状維持とするか。`min_score`を実チャットにも環境変数として露出するか。
2. **ローカル環境での再現確認**: 本書は「ローカル環境未検証」との前提で書かれている。ローカル`docker-compose`環境でも同事象が再現するか、実装・検証フェーズで確認する必要がある（再現しない場合、AWS環境固有の別要因が併存している可能性があり、追加調査が必要）。
3. **実チャットUIへの情報源表示**: 現状、実チャットのエンドユーザー向けUIには情報源（参考情報）を表示する要素がなく、管理者は評価済みメッセージ一覧（`EvaluatedMessagesPage`）の`input`列でのみ確認できる。今回の不具合のような「情報源のズレ」を今後より早く検知できるようにするため、UIへの情報源表示を別途要件として検討するか。
4. **是正の適用範囲**: 本書は`agent_invitro`の`POST /ask-sl`のみを対象とする。`main/ipython/main.py`側のReActエージェント実験（ADR-0022、`graph/agent.py`が自律的に`search_knowledge`を呼ぶ経路）は、`select_tags`→`search_knowledge`の呼び出し方をLLMの自律判断に委ねており、本書の対象外である（ADR-0057同様の前提）。この実験用経路について同種の見直しが必要かは別途判断する。
